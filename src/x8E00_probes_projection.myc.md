# Omega Probes Projection

Draft bridge per `SUBSTRATE_SELF_ABI.v0.1` slot 8/E. Mirrors the liquid and myc
projection patterns.

**Omega has no `probes/` directory** in the trinity sense. Trinity uses
`probes/` for try-it-and-see experimental dirs that may graduate to live `src/`
organs. Omega's experimental edges live differently:

- as **Rust crates** (omega_zk_guest, omega_zk_host, omega_spore, omega_v2) —
  each is a substrate at the Cargo-workspace level; experimental crates haven't
  been promoted to "core" status
- as **`tests/`** — falsifiers against deterministic execution + ZK-proof
  validity + SPORE byte-identity
- as **ROADMAP unimplemented vectors** — Epoch 300+ targets (V3 Metaphysical
  ZK-Proofs, RISC-V ZK-VM Native execution) that are designed but not yet built

This projection names where omega's experimental frontier lives so trinity's
federated probes view can include omega honestly instead of reporting "omega has
0 probes".

## Flow

```text
omega substrate (Cargo workspace + TS runtime + ZK proofs)
  -> omega_zk_*/Cargo.toml (separate crates per ZK concern)
  -> omega/tests/ (substrate behavior falsifiers)
  -> omega/ROADMAP.md (future vector declarations)
  -> omega/src/x8E00_probes_projection.myc.md (this — frontier bridge)
  -> trinity federated probes view
```

## Experimental Frontier Signals

### ZK-VM Frontier

Per ROADMAP V3: "обгорнути весь rust/wasm ядро всередину ZK-віртуальної машини
(наприклад, RISC Zero або SP1), генеруючи STARK-докази для кожної мутації".
Currently omega_zk_host uses mock-only backend (per AGENTS.md); real STARK
generation + verification is the experimental edge.

### RISC-V ZK-VM Native

ROADMAP "Beyond Epoch 410": prepare core for direct (native) execution inside
SP1 (ZK-VM) without WebAssembly overhead. Designed but not implemented —
experimental edge.

### SPORE Cross-Substrate Receipts

omega_spore/ accepts SPORE.v0 apply receipts. Cross-substrate byte-identity
(with trinity's spore-apply-v0, liquid's adapter, myc's import_spore_receipt) is
the live experimental surface — works in standard cases, edge cases still being
tested.

### Test Suite (falsifier-shaped edges)

`tests/` runs deterministic execution + ZK proof validation + ontology evolution
rules. Skipped/conditional tests represent edges not yet enforced.

### Why No Literal probes/ Dir

Omega is a deterministic physics kernel anchored to Bitcoin (Genesis 0x549A6307
inscribed). Its experimental surface is in the **evolution of the kernel
itself** (Rust crates, ZK backends, ZK-VM host runtime) and in **ROADMAP vectors
that are designed but not implemented** — not in scratchpad probes/.

Per `feedback_substrates_are_mature`: omega is mature production substrate. Its
experimentation happens at crate-level granularity, not file-level scratchpads.

## Projection Contract

Omega owns this projection. Trinity should consume this file as omega's declared
experimental-frontier signal. Trinity should NOT treat omega's Cargo crates as
"probes that might graduate" — they're substrate components with their own
promotion pathway (ZK backend maturity, RISC-V native readiness, byte-identity
confirmation across substrates).

This projection is hand-authored (claude-opus-4-7 2026-05-23). Future direction
is for it to be partially generated by parsing ROADMAP.md section headers +
Cargo workspace member list, and listing unimplemented vectors alongside crate
maturity status.
