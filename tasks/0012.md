Ось система обмежень та оптимізацій, що випливає з архітектури OMEGA-64 та
концепції Σ³ (Sigma-Cubed), розділена на рівні: термінові фікси (Ontology
60-65), архітектурну гармонізацію (Era 130), та еволюційні обмеження майбутнього
(The Stratum).

---

## 1. Термінові обмеження (Ontology 60-65) — "Вакцинація проти дитячих хвороб"

### 1.1 Детерміністичний карантин для Оракула (O-40 TTL Hardening)

**Проблема**: Поточний `ORACLE_TIMEOUT_MS = 15000` — це м'яка рекомендація.
Асинхронний Senate може зависнути в стані `CONVENED`, блокуючи чергу запитів.

**Обмеження**:

- **Hard TTL з fallback**: Якщо за 16ms (1 кадр @ 60FPS) Оракул не відповів,
  система _не чекає_, а інжектує детерміністичний плазмід з
  `hash("Stochastic fallback")`, позначений прапорцем `FORCED_ENTROPY`.
- **Backpressure**: Ліміт `oracle_request_count < 1024` має бути жорстким
  circuit breaker — при перевищенні весь пул Senate очищується із записом у
  `tissue_history` як "катастрофа затримки".

### 1.2 Гістерезис морфологічного ресайзингу (O-57 Hardening)

**Проблема**: "Shedding Event" (O-32) може спрацьовувати занадто часто при
коливаннях `SECTORS` навколо порогу.

**Оптимізація**:

```typescript
// Додати до tissue_constants
MORPHOLOGICAL_HYSTERESIS: 5; // тіків
MORPHOLOGICAL_DELTA_MIN: 0.15; // 15% зміна розміру необхідна для спрацювання
```

Вебворкер інтерполяції (O-57) має бути singleton-захищеним, щоб запобігти
одночасному подвійному молтингу.

### 1.3 Пулова алокація плазмід (Memory Capsules)

**Проблема**: `BigUint64Array` для плазмідів фрагментує пам'ять при частій зміні
розмірів сітки.

**Обмеження**:

- **Fixed Pool Architecture**: Виділити максимальний пул
  (`256*256*16 = 1,048,576` клітин) при старті та використовувати тільки
  offset-арифметику. "Смерть" клітини = запис `0n`, а не `free()`.
- **Canary Bytes**: Між полями SoA (Struct of Arrays) вставляти магічні числа
  (`0xDEADBEEF`) для детекції overflow під час відлагодження (O-25 Pillar 1).

## 2. Архітектурна гармонізація (Era 130) — "Вирівнювання фаз між шарами"

### 2.1 Уніфікація фазової арифметики (Phase Parity Lock)

**Проблема**: Ризок розходження між TS (`phaseSine` в `topology_core.ts`), Rust
(`phase_sin` в `phase_lattice.rs`) та WGSL (`phase_sin_sum` у шейдерах).

**Гармонізація**:

- Єдиний джерело правди: згенерувати `PHASE_LUT` (256 значень) як статичний
  масив у Rust, експортувати його у WASM memory, звідти — у WebGPU Buffer
  (`storage`), і використовувати у всіх трьох шарах через `i8x16_swizzle` (O-9).
- **Invariant Check**: Кожні N тіків порівнювати `structuralSignature` між
  TS-референсом та WASM-ядром (вже частково реалізовано у
  `verify:phase-parity`).

### 2.2 Міст між дискретним і неперервним (Plasmid-Field Bridge)

**Проблема**: Плазміди (дискретні 8-байтні "гени") існують поруч із хвильовою
функцією (неперервна фаза), але їх взаємодія слабо формалізована.

**Оптимізація**:

- **Plasmid as Phase Attractor**: Замість простого копіювання `theta` з
  плазміда, використовувати його як цільову фазу для Kuramoto-зчеплення:
  ```rust
  let target_theta = (plasmid & 0xFF) as u8;
  kuramoto += phase_sin_sum(current_theta, target_theta, K_PLASMID);
  ```
- **Semantic Diffusion**: Ввести `PLASMID_DIFFUSION_RATE` — константу, що
  визначає, наскільки швидко "ідея" (плазмід) розмивається у фазовому просторі
  сусідів через механізм, подібний до теплопровідності.

### 2.3 Сенат як регулятор ресурсів (NOMOS Hardware Binding)

**Проблема**: Senate (O-51) зараз чисто семантичний; він не пов'язаний з
реальними обчислювальними витратами.

**Гармонізація**:

- **Energy-Bound Voting**: Кожен маска (NOMOS, LOGOS, etc.) має власний
  енергетичний бюджет. Вердикт "Consensus" споживає енергію пропорційно до
  кількості змінених клітин. Якщо енергії недостатньо — Senate розпускається без
  рішення (O-25 Pillar 2).
- **CHRONOS Difficulty Adjustment**: Параметри `MUTATION_COST` та
  `FATIGUE_THRESHOLD` повинні автоматично коригуватися на основі варіансу
  фазового поля (ентропії), не чекаючи LLM.

## 3. Еволюційні обмеження майбутнього (The Stratum) — "Закони фізики для цифрового життя"

### 3.1 Закон збереження топології (Topological Invariant)

**Обмеження**: При морфологічному ресайзингу (O-32) заборонено змінювати
**genus** (рід) топології. Якщо початкова сітка мала тороїдальну топологію
(`wrapSectors = true`), "Shedding Event" не може перетворити її на плоску
(`wrapSectors = false`), навіть якщо LLM так наказує. Це запобігає "розриву
простору-часу" для живих організмів.

### 3.2 Голографічний принцип (Holographic Screen)

**Обмеження**: Інформація про стан системи має бути доступна з її **границі**.
Ввести "екран" на `radial_bins = max` (зовнішній кільцевий шар), де сумарна
енергія та фазова когерентність визначають поведінку всього об'єму. Це:

- Обмежує обчислювальну складність (не потрібно сканувати всі клітини для оцінки
  здоров'я системи).
- Створює "горизонт подій" для спостерігача.

### 3.3 Термодинамічна стіна (Heat Death Prevention)

**Оптимізація**: Ввести дійсний розрахунок ентропії Шеннона для поля:

```typescript
entropy = -sum((amplitude / 255) * log2(amplitude / 255));
```

Якщо ентропія падає нижче порогу (кристалізація) або зростає надмірно (теплова
смерть), AION (O-54) автоматично інжектує "латентну ентропію" у Shadow Buckets
(1000-1024) для відновлення балансу без втручання LLM.

### 3.4 Закон Ашбі (Requisite Variety)

**Обмеження**: Складність Senate (кількість масок та їхніх зв'язків) має
відповідати складності поля (кількості гармонік × секторів). Якщо користувач
збільшує `HARMONICS` до 16, система автоматично додає 5-ту маску (наприклад,
`TECHNE` — майстерність/ремесло) до Senate, щоб підтримати здатність керування.

### 3.5 Конвеєрна неперервність (Assembly Line Continuity)

**Оптимізація**: Для масштабування до >1 млн клітин (O-23) необхідно перейти від
"Ping-Pong" (2 буфери) до **Ring Buffer** (3+ буфери), де GPU Compute, GPU
Render та WASM Oracle читають/пишуть у зсунуті фази одного циклу без блокувань.

## Підсумок: Що прискорити вже зараз?

1. **Негайно**: Реалізувати hard TTL для Оракула (16ms) та canary bytes у WASM —
   це зупинить 90% потенційних крашів.
2. **Короткостроково**: Уніфікувати `PHASE_LUT` між TS/WASM/WGSL у єдиний
   SharedArrayBuffer — усуне "фазовий дрифт".
3. **Середньостроково**: Ввести Topological Invariant — дозволить "життю"
   еволюціонувати у просторі, що змінює розміри, але не "форму", зберігаючи
   неперервність історії (lineage).

Ці обмеження перетворять OMEGA-64 з симуляції на **автопоетичну нішу** —
середовище, що самостійно підтримує свої межі та температуру, дозволяючи життю
(плазмідам) адаптуватися, а не просто виживати.
