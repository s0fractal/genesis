# Task 0156: Era 1700 — Translation Policy Corroboration Wire Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1690 made policy-drift warrant emission optionally dependent on
multiple independent witnesses. But external witness records still had
to be injected locally. The mesh needed a compact wire payload for
corroboration raises.

## Objective
1. Define a compact corroboration raise payload.
2. Validate raises by recomputing the semantic drift hash.
3. Feed valid remote raises into `TranslationPolicyCorroborationTracker`.
4. Add mesh bridge helpers and passive WebRTC dispatch.

## Design Notes
- **Why validate the drift hash at ingestion?** Corroboration only means
  anything if every witness is counted against the same semantic drift.
  Recomputing prevents malformed or inconsistent payloads from raising
  confidence.
- **Why keep WebRTC passive?** The mesh transports evidence; the
  application-owned loop decides whether a corroborated drift should
  become a warrant proposal.
- **Why include pair counts?** The policy hash alone is opaque.
  Pair-count metadata gives cheap diagnostics and is part of the
  equivalence hash.
