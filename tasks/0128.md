# Task 0128: Era 1420 — Spore-Initiated Event Broadcast

## Status: COMPLETED | Priority: HIGH

## Context
Era 1410 added wire frames for event sync but the encode side
existed only in JS. The Cortex-M4F spore could receive event-delta
envelopes but could not originate them. Era 1420 ports the encode
path to Rust with byte-for-byte JS parity.

## Objective
1. Rust frame builders for `EVENT_HASH_LIST` and
   `EVENT_DELTA_CHUNK` (header + record variants).
2. `pack_kind_tag` mirroring JS `packKindTag` byte-for-byte.
3. `BroadcastBuffer<const N>` for `no_std`-clean outgoing-frame
   FIFO.
4. Helper for converting frames into a contiguous wire byte buffer.
5. Cross-substrate locked vectors pinning the envelope hash in
   THREE places: Rust unit tests, JS unit tests, and the existing
   Era 1400 sink anchors.

## Design Notes
- **Why locked envelope hash in three places?** Two locks (Era
  1400 sink + Era 1420 chunker) catch single-sided drift. A
  third (JS-side chunkEventDelta) catches the case where the JS
  chunker would compute the wire hash differently than the JS
  hash-set primitive. Three independent computations of the same
  bit pattern from independent code paths makes silent
  divergence essentially impossible.
- **Why does `BroadcastBuffer` evict on overflow instead of
  failing?** Predictability under pressure. A microcontroller's
  flush latency varies; the buffer fills when the wire is slow.
  Refusing new frames during a backlog would cause silent loss
  of NEW events while the old ones eventually get sent —
  worse forensic outcome than dropping the oldest. Eviction
  with a `false` return lets caller log the pressure event
  without halting the loop.
- **Why a separate `broadcast_tick` helper?** Cortex-M4F nodes
  often lack RTC. They have a free-running counter (SysTick) and
  their relay_id. Combining these via FNV-1a gives a "tick" that:
  (a) advances monotonically, (b) doesn't collide between spores
  with the same counter value, (c) is deterministic for tests.
  The tick isn't wall-clock — it's just an ordering anchor.
- **Why does `build_delta_chunk_frames` accept entries in caller-
  order rather than sorting internally?** Sorting on a
  microcontroller's tiny stack with a borrowed slice is awkward
  (`slice::sort` needs a comparator and may bloat). Caller can
  use `event_hash_set_hash`'s built-in sort path or maintain
  entries pre-sorted. Documented expectation; tests use
  pre-sorted input.
