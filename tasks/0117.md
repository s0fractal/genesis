# Task 0117: Era 1310 — Periodic Archive Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1300 archives are deterministic + integrity-checked, but
shipping a full archive every sync wastes bandwidth when only a
few digests differ. Era 1310 defines a delta-exchange protocol
that converges two archives by sending only the missing records.

## Objective
Provide pure functions for the three-phase sync handshake:
1. Initiator publishes `ArchiveDigestList` (its known digests).
2. Peer computes `ArchiveDelta` (records the initiator lacks +
   the digests the peer itself lacks).
3. Initiator applies the delta with integrity verification.

After two such exchanges (A→B then B→A), both archives are
guaranteed identical.

## Acceptance Criteria

### 1. Sync Module ✅
- [x] `src/network/archive_sync.ts`:
  - `digestSetHash(digests)` — order-independent FNV-1a over
    sorted digest set (matches Era 1300's `computeArchiveHash`).
  - `buildDigestList(bundle, now_ms)` — manifest construction.
  - `computeDelta(initiator_list, peer_records, now_ms)` —
    pure function returning `{missing_records, peer_missing_digests,
    delta_hash}`.
  - `applyDelta(local_records, delta)` — verifies integrity,
    rejects collisions, returns merged records + `outcome`.
  - `syncRound(a, b, now_ms)` — runs both directions; returns
    `{a_added_from_b, b_added_from_a, converged_records,
    converged_digest_set_hash}`.

### 2. Determinism ✅
- [x] `digestSetHash` is order-independent (sorts before hashing).
- [x] Empty digest set hashes to FNV-1a offset basis (`0x811C_9DC5`).
- [x] `delta_hash` covers the missing records' digest set, not
  records themselves — symmetric with Era 1300's archive_hash.
- [x] `syncRound` produces identical converged sets regardless of
  initiator order.

### 3. Integrity Verification ✅
- [x] `applyDelta` rejects bad sync schema.
- [x] `delta_hash` drift triggers rejection (tampering detection).
- [x] Records with bad archive schema (Era 1300) rejected.
- [x] Digest collisions (same digest, different content) rejected
  rather than silently overwritten — preserves the "FNV-1a
  digest is content-addressing" invariant.

### 4. Idempotency ✅
- [x] Identical records in delta + local set → silently skipped
  (re-running sync is safe).
- [x] Empty delta is a no-op (no false additions).

## Design Notes
- **Why `peer_missing_digests` in the delta?** The peer can
  immediately tell the initiator which digests IT (the peer)
  lacks, so the symmetric A→B direction in `syncRound` doesn't
  need a separate digest-list broadcast. One delta carries
  both directions of "what's missing".
- **Why reject collisions instead of overwriting?** A digest
  is supposed to be uniquely derived from a verdict's content
  (Era 1280's FNV-1a over inputs+outputs). If two parties
  disagree on what's at a given digest, that's corruption —
  silent overwrite would hide the problem and break
  chain-of-custody.
- **Why include `peer_missing_digests` BUT NOT the corresponding
  records?** Bandwidth optimization. The peer announces *which*
  digests it lacks; the initiator decides *whether* to send them
  (e.g. the initiator may not want to ship records the peer is
  missing for unrelated policy reasons). Decoupling
  identification from transmission keeps the protocol flexible.
- **Why not use Bloom filters?** With a typical archive of
  thousands of digests, naive set-difference is already O(N)
  with constant factors small enough to not need probabilistic
  data structures. Bloom filters would add false-positive
  handling complexity without bandwidth wins at this scale.
