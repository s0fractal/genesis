# Task 0169: Era 1830 - Translation Policy Forensic Event Sink Adapter

## Status

✅ COMPLETED

## Context

Era 1820 made translation-policy telemetry subscribable via
`translationPolicyTelemetry` events. The stream was still operational
diagnostics only: useful to watch live, but not automatically anchored
into the forensic event chain.

## Implementation

- Added `src/network/translation_policy_forensic_event_adapter.ts`.
- Introduced `TRANSLATION_POLICY_FORENSIC_EVENT_ADAPTER_SCHEMA =
  "OMEGA-1830/v1"`.
- Added `TranslationPolicyForensicEventAdapter`, which:
  - subscribes to `translationPolicyTelemetry` through the existing
    transport-agnostic `EventSource` contract;
  - appends compact `kind="tpol"` records to `ForensicEventSink`;
  - uses HUD-compatible bands for normal runtime states;
  - adds dedicated `disabled`, `install-error`, and `tick-error` bands;
  - records local policy hash, pair count, peer counts, drift counts,
    malformed counts, proposal counts, install/tick errors, and source
    telemetry hash;
  - suppresses source-event-hash churn and appends only when the compact
    forensic projection changes;
  - exposes lifecycle and malformed/append/skipped telemetry.
- Kept bootstrap decoupled from sinks: consumers opt in by wiring the
  adapter to the telemetry event source and a chosen `ForensicEventSink`.

## Tests

- `tests/translation_policy_forensic_event_adapter_test.ts`
  - disabled adapter is inert;
  - start/stop subscribes and unsubscribes;
  - compact events append to the sink and preserve chain integrity;
  - unchanged forensic projections are skipped;
  - policy-hash and band changes append;
  - install/tick errors map to dedicated bands;
  - malformed details are counted;
  - custom event name and kind work;
  - source hash churn is ignored by the forensic projection;
  - schema constant.
