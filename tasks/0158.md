# Task 0158: Era 1720 — Translation Policy Mesh Broadcast Scheduler

## Status

✅ COMPLETED

## Context

Era 1710 closed inbound live wiring for translation-policy claims and
corroboration raises. The remaining outbound gap was that local policy
claims were still caller-triggered. Operators needed a deterministic
per-peer scheduler for periodic mesh broadcast without spamming peers
with identical policy hashes.

## Implementation

- Added `src/network/translation_policy_broadcast_scheduler.ts`.
- Introduced `TRANSLATION_POLICY_BROADCAST_SCHEMA = "OMEGA-1720/v1"`.
- Added `TranslationPolicyBroadcastScheduler` over the existing
  `TranslationPolicyMeshBridge`.
- Reused Era 1330 scheduler primitives for per-peer attempt/success/
  failure state and exponential backoff.
- Added known-peer management: `addPeer`, `removePeer`, `clear`,
  `snapshot`, `peerCount`, `duePeers`.
- Added `tick(now_ms, max_peers)` that:
  - builds one local policy claim per tick;
  - walks peers in deterministic peer-id order;
  - respects cooldown and cold-peer classification;
  - sends changed policy hashes immediately when due;
  - suppresses unchanged policy claims until a configurable refresh
    horizon expires;
  - records success/failure telemetry per decision.
- Added `recordExternalSuccess(...)` so callers can seed scheduler state
  when a claim was sent by another path.
