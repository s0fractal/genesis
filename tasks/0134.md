## Design Notes
- **Why a parallel accumulator instead of a unified one?** Frame
  types HASH_RESPONSE and DELTA_CHUNK have different wire layouts
  (4 hashes vs 1 entry per chunk, different reserved-byte
  packings). A unified accumulator would need a discriminated
  union and conditional decode logic — more code, more bug
  surface. Parallel reassemblers keep each path linear and
  obviously correct.
- **Why drain-once `take_peer_hashes`?** Once the convergence
  driver has consumed a peer's hash list and computed the
  diff/ship action, holding the data further wastes capacity for
  the next response. The Option-take pattern is idiomatic Rust
  for "consume and clear".
- **Why does `maybe_answer_pending_request` clear the pending
  state on success?** Otherwise the next tick would re-send the
  same response. The pending fields exist precisely to bridge
  one tick to the next; once answered, they're done.
- **Why `MAX_RESPONSE_HASHES = 64`?** Matches the typical sink
  capacity. Larger values waste static SRAM; smaller values
  truncate. 64 is a round number that aligns with the
  `MAX_ANCHOR_HASHES` cap from Era 1400.
- **Why `ship_hash_list` re-sorts internally instead of trusting
  sink order?** The sink stores entries in append order, but the
  HASH_RESPONSE protocol sends them sorted ascending so the
  receiver gets a deterministic list. Internal sort means callers
  don't need to remember ordering rules.

## Next Era Trigger
**Era 1490: ConvergenceDriver Auto-Pipeline.** Era 1480 has all
the primitives wired but a caller still has to drive the state
machine: detect mismatch → ship_hash_request → wait → take_peer_hashes
→ compute_missing_indices → ship_delta. Era 1490 will encapsulate
this dance inside `ConvergenceDriver` so a single `step` call:
- Picks the highest-priority mismatched peer.
- Issues HASH_REQUEST and remembers the request_id + deadline.
- On next ticks, watches `take_peer_hashes`; if matching the
  expected request_id, computes diff and ships it.
- On deadline expiry, marks the attempt as failed (record_sync_failure).
- Cleans up state on success (record_sync_success).
End-to-end test: `auto_pipeline_converges_under_paired_runners`.
