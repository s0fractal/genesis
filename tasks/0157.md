# Task 0157: Era 1710 — Translation Policy Live Wiring Adapter

## Status

✅ COMPLETED

## Context

Era 1700 made translation-policy corroboration raises wire-carryable, but
the production mesh path still required callers to manually subscribe to
`translationPolicyClaim` and `translationPolicyCorroborationRaise` events.
That left an operational gap between passive WebRTC dispatch and the Era
1680/1690 investigation loop.

## Implementation

- Added `src/network/translation_policy_live_wiring_adapter.ts`.
- Introduced `TRANSLATION_POLICY_LIVE_WIRING_SCHEMA = "OMEGA-1710/v1"`.
- Added `TranslationPolicyLiveWiringAdapter` with idempotent
  `start()` / `stop()` lifecycle over the existing `EventSource` contract.
- Claim events now route directly into
  `TranslationPolicyInvestigationLoop.ingestPolicyBody(...)`.
- Corroboration raise events now decode and record into the loop's
  configured `TranslationPolicyCorroborationTracker`.
- Added explicit telemetry for received, malformed, observed, recorded,
  emitted, failed, and skipped paths.
- Added optional local raise emission after a local drift observation,
  using the loop's corroboration witness id by default and a deterministic
  target resolver.

## Invariant Notes

- No physics path touched.
- No random behavior introduced.
- Existing single-observer warrant behavior is unchanged unless callers
  explicitly enable corroboration gates or local raise emission.
- The adapter owns lifecycle and telemetry only; monitor, loop, tracker,
  and mesh bridge remain the sources of truth.
