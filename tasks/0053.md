Давайте проаналізуємо цю кодову базу та оптимізуємо її для LLM-споживання. Видно
кілька патернів, які "з'їдають" токени без доданої вартості.

## 🔍 Ключові проблеми

### 1. **Переускладнена номенклатура**

- `OMEGA-64`, `Ontology 42`, `Era 64 (The Stratum)`, `Genesis Spore`
- `PhaseAgent`, `PhaseLatticeField`, `PhaseComputeEngine`, `PhaseWebGPUObserver`
- `SovereignOracle`, `SemanticCoupler`, `ThermodynamicSubsystem`

### 2. **Дублювання констант між Rust/TS/WGSL**

- Kuramoto coupling визначений у 3+ місцях
- Фізичні константи розсіяні по файлах

### 3. **Надмірна абстракція**

- `ISubsystem` інтерфейс для 4 класів
- Окремі менеджери замість прямих викликів

### 4. **WGSL шейдери займають ~40% токенів**

- Коментарі-есе всередині шейдерів
- Дубльована логіка між `compute_kuramoto.wgsl` та `compute_mycelial.wgsl`

```wgsl
// Фізика: Kuramoto + генетичний резонанс
struct Params { 
    dims: vec3u, time: f32,      // 0-15
    coupling: vec4i,             // Kuramoto params
    thresholds: vec4i,           // Lock/high/res/align
    inject: vec4u,               // idx, hash_lo, hash_hi, bucket
    pad: vec4u,                  // alignment
}

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) gid: vec3u) {
    let idx = gid.x;
    if (idx >= params.dims.x * params.dims.y) { return; }
    
    let me = load(idx);
    let neighbors = array(
        load(left(idx)), load(right(idx)), 
        load(inner(idx)), load(outer(idx))
    );
    
    // Σ coupling * sin(Δθ)
    var torque = 0i;
    for (var i=0; i<4; i++) {
        torque += sin(me.θ - neighbors[i].θ) * params.coupling.x;
    }
    
    // Зберегти з ін'єкцією
    store(idx, step(me, torque), params.inject.x == idx);
}
```

## 🧠 Принципи "LLM-first" коду

1. **Імена = поведінка**, не метафора
   - `tickPhysics()` замість `ThermodynamicSubsystem.tickHomeostasis()`

2. **Коментарі = "чому"**, не "що"
   - `// Запобігаємо замерзанню при entropy < 2` замість 5 рядків філософії

3. **Один джерело істини**
   - Константи генеруються в один JSON → Rust/TS/WGSL

4. **Плоска ієрархія**
   - Функції > Класи > Інтерфейси > Фабрики
