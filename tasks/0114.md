# Task 0114: Era 1280 — Forensic Quorum

## Status: COMPLETED | Priority: HIGH

## Context
Era 1270 lets N relays merge their frame logs for cross-perspective
forensic reconstruction. Era 1280 closes the post-mortem loop:
when the merged replay produces metrics that MATCH (within
tolerance) the real-time alarm that fired during the incident,
we have a "forensic quorum" — independent multi-relay
reconstruction has agreed with the live signal.

## Objective
Provide an adjudication function that takes (alarm_fingerprint,
relay_recorders) and returns a verdict in
`{corroborated, uncorroborated, insufficient-relays, empty-window}`
plus enough metadata for archival reports.

### 2. Verdict Logic ✅
- [x] **insufficient-relays** if `relay_count < min_relays`
  (default 3). Verdict before any merge work.
- [x] **empty-window** if no frames intersect the requested
  window across all input recorders. Distinct from
  uncorroborated.
- [x] **corroborated** iff merged-replay redundancy_q16 differs
  from `observed_q16` by `≤ tolerance_q16` (default 6553 ≈ 10%).
- [x] **uncorroborated** otherwise. Operator can drill into
  `diff_q16` to see how far off.

### 3. Determinism ✅
- [x] `digest` is FNV-1a over (source_relay_id, observed_q16,
  sorted relay_ids, replayed_q16, diff_q16). Two operators
  running the same adjudication get identical digests for
  archival.
- [x] Recorder iteration order is normalized via sorted relay_ids
  before merge.

### 4. Window Filtering ✅
- [x] Each recorder's frames are filtered to
  `[window_start_ms, window_end_ms]` before merging. Out-of-
  window observations don't pollute the redundancy computation.

### 5. Tests ✅
- [x] 17 Deno tests cover: corroborated (replay matches alarm),

## Design Notes
- **Why is `digest` part of the verdict?** Forensic reports
  reference adjudications by their digest. If two parties
  computed the same adjudication independently, they'll get
  the same digest — proving they used the same inputs without
  sharing the recorders themselves. Useful for chain-of-custody
  audit trails.
- **Why default tolerance 6553 (≈10%)?** Same as Era 1190's
  partition threshold. The intuition: if live alarms and
  cooperative replay agree to within Era 1190's "this is
  agreement" zone, they're forensically equivalent.
- **Why is "uncorroborated" not "rejected"?** Three
  possibilities for replay-vs-alarm divergence: (1) alarm was
  spurious, (2) merge missed frames the live alarm saw,
  (3) live alarm misread the metric. Forensic reports flag
  the disagreement; operators investigate the cause. The
  module doesn't pre-judge which of (1)-(3) is true.
- **Why exclude `verdict` field from `digest`?** Two parties
  might disagree on the tolerance threshold and thus the
  verdict, but the underlying numbers (replayed_q16,
  diff_q16) are deterministic. The digest captures the facts;
  the verdict is the interpretation.
