Я подивився на твою систему як на живий організм, а не як на код. Вона вже дуже
сильна — але зараз вона більше схожа на **замкнену екосистему**, ніж на таку, що
здатна проростати назовні.

Тому не буду “оптимізувати” — я покажу, де в ній є **потенціал для мутації
наступного рівня**.

---

## 🌱 1. Ти вже зробив головне — але застряг у шарі “локального життя”

У тебе є:

- фізика (WebGPU lattice)
- генетика (combinatory logic)
- економіка (energy)
- еволюція (oracle + senate)
- памʼять (`event_ledger`, snapshots)

Але це все існує **в межах одного торуса**.

👉 Проблема:

> система не має справжнього _зовнішнього тиску середовища_

Зараз:

```
evolution = f(internal dynamics)
```

А має бути:

```
evolution = f(internal dynamics + external constraints)
```

---

## 🔥 2. Додай “реальність” як силу, а не як інтерфейс

Твій `PhaseNetwork` — це вже портал, але він слабкий семантично.

### Що зробити:

Перетвори мережу з:

```ts
broadcastPlasmid(hash, bucket, energy);
```

в:

```ts
broadcastIntent({
  hash,
  phenotype,
  required_energy,
  survival_contract,
  external_dependency,
});
```

👉 Ідея: агенти мають **виживати не тільки в lattice**, а й у зовнішньому світі:

- API
- файли
- інші агенти
- люди

## 🧠 3. Oracle зараз — суддя. Зроби його сліпим

Зараз у тебе:

```ts
oracle.tickHomeostasis(entropy);
oracle.prune / breed;
```

Це централізована воля.

### Проблема:

це **бог**, а не фізика.

---

### Зміна:

Перетвори Oracle в:

> **локальне поле впливу, а не глобальний контроль**

Замість:

```ts
oracle decides
```

зроби:

```ts
agents predict oracle
```

Тобто:

- oracle не каже “виживеш / помреш”
- oracle створює **градієнт тиску**

interface Phenotype {
