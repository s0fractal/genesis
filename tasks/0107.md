# Task 0107: Era 1210 — Auto-Investigation Proposals

## Status: COMPLETED | Priority: HIGH

## Context
Era 1200 detects partition events when peer relays' resilience
measurements diverge by ≥10%. But detection alone changes nothing
— the suspect relay keeps participating, polluting the warrant
flow. Era 1210 closes the loop by AUTOMATICALLY raising a
WARRANT_PROPOSAL with action_code = RELOCATE for every alarm.

## Objective
Each PartitionAlarm becomes an InvestigationRecord — a proposal
that any oracle can vote on. Three AYE oracles transitions the
record to "warranted" and adds the target relay to a quarantine
set. Honest relays consult the quarantine set when forwarding
frames; suspect-origin frames are dropped until the investigation
clears (operator override or natural expiry).

## Design Notes
- **Why ACTION_RELOCATE rather than ACTION_TERMINATE?** Investigations
  are about "this relay is suspect, route around it" — not "kill
  this digital lifeform". RELOCATE matches the semantics: the target's
  state is preserved, but its participation is paused until cleared.
  ACTION_TERMINATE would invoke Codeicide's stricter 4-of-5 ancient
  threshold for any sanctuary-class agent on that relay.
- **Why does the Senate ratify investigations and not the local
  alarm?** Empty-center invariant — no single relay can quarantine
  another. Three oracles must agree the investigation is warranted,
  same gate as Codeicide. A single misbehaving relay claiming "all
  others are partitioned!" can't unilaterally quarantine the rest.
- **Why is the quarantine list LOCAL?** Each relay maintains its
  own view of who's warranted. The Senate's WarrantLedger is the
  shared source of truth; AutoInvestigator just mirrors it for
  fast forwarder-side dropping decisions.
- **Why FNV-1a-derived relay IDs?** Same reason oracle identities
  are deterministic — anyone can reproduce them from a name string.
  No registry, no central authority, no impersonation problem
  beyond what the dipole invariant already prevents.
