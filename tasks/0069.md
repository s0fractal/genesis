# VECTOR IV | ERA 300: ATP Osmosis (On-Chain Energy)

Цей документ описує архітектуру переходу до **Proof-of-Useful-Work (PoUW)** та токенізації обчислювального газу через смарт-контракти (Solana / Base).

## 1. Концепція (ATP як Газ Симуляції)

В епоху 280 ми впровадили ZK-STARK докази для перевірки `LambdaArena`. Епоха 300 об'єднує цю криптографію з Web3 економікою.
Термодинамічний простір OMEGA-64 вимагає енергії для підтримки фазової когерентності та ін'єкції нових плазмід. Ця енергія формалізується як токен **ATP**.

- **Minting (Екзотермічна Реакція):** Коли Worker (нода) успішно еволюціонує `Phenotype` з високою когерентністю, він генерує SP1 ZK-Proof та відправляє його у смарт-контракт. Контракт верифікує доказ і карбує (mints) ATP токени на гаманець ноди (Proof-of-Useful-Work).
- **Burning (Ендотермічна Реакція):** Щоб інвестувати новий код (Plasma/AST) у Macro-Torus (передати `FOREIGN_PLASMID` сусідам), автор плазміди має спалити ATP. Це захист від спаму ідеального рівня.

---

## 2. Архітектура ATP Bridge (`src/network/atp_bridge.ts`)

Ми створюємо універсальний міст, здатний підключатися до EVM (Base/Arbitrum) або Solana.

### Інтерфейс
```typescript
export interface ATPTransactionReceipt {
    txHash: string;
    atpAmount: number;
    confirmed: boolean;
}

export interface IATPBridge {
    // Відправити ZK Proof у контракт для генерації енергії
    mintATP(proofBytes: string, morphologyHash: string, wallet: string): Promise<ATPTransactionReceipt>;
    
    // Спалити ATP для права розповюдження плазміди
    burnATP(amount: number, morphologyHash: string, wallet: string): Promise<ATPTransactionReceipt>;
    
    // Перевірити поточний запас енергії ноди/гаманця
    getBalance(wallet: string): Promise<number>;
}
```

## 3. Інтеграція з `WebRTCMesh`

Додаємо перевірку ліквідності у `FOREIGN_PLASMID` реле:
1. Коли нода підключається до Mesh, вона анонсує свій `walletAddress`.
2. При отриманні `FOREIGN_PLASMID` окрім валідації `verify_sp1_receipt`, Mesh вимагає прикласти `burnTxHash` (хеш транзакції спалювання ATP на блокчейні).
3. Якщо транзакція дійсна (перевірка через `atp_bridge`), плазміда пропускається в `SharedArrayBuffer` до фізичного рушія!
