# Task 0132: Era 1460 — Convergence Driver (Anchor-Mismatch Initiation)

## Status: COMPLETED | Priority: HIGH

## Context
Era 1450's runner recorded `last_peer_anchor` but never acted on
mismatches. Era 1460 adds the driver layer that decides when to
ship a delta to which peer, respecting Era 1430's scheduler so
flaky peers don't trigger storms.

## Objective
1. `ConvergenceDriver<const M>` — fixed-table per-peer state
   (anchor + scheduler slot).
2. `observe_peer_anchor(peer_id, anchor)` — record/update; first-
   sighting returns true.
3. `select_targets(local_anchor, now_ms, &mut [u32]) -> usize` —
   priority-ordered peer_ids ready for sync.
4. `ship_to_peer(runner, driver, peer_id, entries, now_ms)` —
   wraps `ship_delta` with attempt/success/failure bookkeeping.
5. Diagnostic counters.

## Design Notes
- **Why ship full set instead of precise set-difference?** The
  spore doesn't have the peer's full hash list — only the peer's
  anchor (a single FNV value). Computing real set-difference
  would require requesting the peer's list (Era 1470 work).
  Idempotent skip on apply makes "ship everything" correct,
  just bandwidth-suboptimal. Sink capacities in the dozens make
  this an acceptable tradeoff for now.
- **Why oldest-attempt-first ordering?** Fair rotation. A peer
  that was selected last cycle deserves to wait while the
  driver attends to others. Without this, a stable mismatch on
  one peer would starve the others.
- **Why exclude cold peers entirely instead of demoting them?**
  Same rationale as Era 1340's coordinator: bypassing cooldown
  for an alarm doesn't fix a permanently-broken partner. Cold
  is a different signal — partner is dead, not slow — and
  convergence work to such a peer is wasted bandwidth.
- **Why not auto-call `select_targets` + `ship_to_peer` from
  inside the runner?** Layering. The runner is dumb glue
  between wire and protocol; the driver is where policy lives.
  Keeping them separate makes alternative drivers (e.g. one
  that consults a reputation oracle, or one that prioritizes
  by HALO state) straightforward to drop in.
- **Why drop `Eq` from `PeerEntry`?** `PeerSyncSlot` doesn't
  derive `Eq`, and we don't actually need entry equality in
  this Era. Dropping it lets `Clone, Copy` survive without
  cascading derive requests.

## Next Era Trigger
**Era 1470: Hash-List Request/Response Frames.** Era 1460 ships
the full local set on mismatch — correct but bandwidth-suboptimal.
Era 1470 will add `FRAME_TYPE_EVENT_HASH_REQUEST = 11` and
`FRAME_TYPE_EVENT_HASH_RESPONSE = 12` so a spore can:
1. Detect anchor mismatch, send a HASH_REQUEST.
2. Peer responds with chunked HASH_RESPONSE frames carrying
   its full hash list.
3. Local computes precise set-difference, ships only those
   entries the peer is missing via Era 1410 wire format.
This converts "ship everything, dedup at apply" into "compute
diff, ship only missing" — typical mesh efficiency improvement
of 50-90% depending on overlap.
