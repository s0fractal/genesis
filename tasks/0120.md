# Task 0120: Era 1340 — Multi-Peer Sync Coordinator

## Status: COMPLETED | Priority: HIGH

## Context
Eras 1310–1330 each address a single dimension of the sync problem:
- Era 1310: pure delta exchange.
- Era 1320: chunk + reassemble over the wire.
- Era 1330: per-peer scheduling + per-envelope retransmission.

A real relay tracks many peers, may have several envelopes in
flight at once, and needs operator-visible telemetry. Era 1340
introduces the top-level `CoordinatorState` that owns all of this.

## Objective
Provide a pure-functional coordinator API that:
1. Tracks N peer schedule states + M in-flight envelopes.
2. Picks next sync candidates by priority order.
3. Routes incoming frames to the right envelope and tracks per-peer
   contribution attribution.
4. Wraps Era 1330's `decideAction` with peer fan-out info.
5. Computes a Q16 fleet convergence rate.
6. Exposes telemetry counters.

### 8. Bug Fix in Era 1330 ✅
- [x] `shouldSyncNow` previously had a "fresh peer" branch that
  returned `true` when `consecutive_failures === 0 &&
  last_attempt_ms === 0`. This created a hole when
  `recordSyncSuccess` was called without a prior attempt — the peer
  appeared "never attempted" again because we don't update
  `last_attempt_ms` on success. Simplified to
  `now_ms >= state.next_attempt_ms`. Initial state has
  `next_attempt_ms = 0`, so fresh peers still go through; updated
  state respects the gate. Era 1330 tests still pass.

## Design Notes
- **Why fan out retransmit to all contributors instead of just the
  originator?** A peer that contributed any frame for the envelope
  has demonstrated it knows about the envelope at all. Fanning out
  to all contributors increases recovery probability without much
  extra cost — caller can choose to ask only the originator if
  bandwidth-constrained.
- **Why Q16 for `fleetConvergenceRate`?** Consistent with Era 1240's
  composite health score, Era 1140's reputation rates, and
  everywhere else integer-fixed-point appears in the protocol.
  This metric will plug into Era 1350's COMPOSITE_HEALTH
  broadcasting without conversion.
- **Why is "empty network = 65536"?** Vacuous convergence. With no
  network-known digests, there's nothing to sync; reporting
  divergence (or NaN) would create false alarms during bootstrap.
- **Why does a local superset still report 65536, not >65536?** The
  metric measures coverage, not information advantage. A relay
  that has *more* than the network union is not "more than
  converged" — it has corroborated everything the network knows
  (the question this metric answers). Information-advantage
  detection belongs in a separate signal.
- **Why are sources tracked separately from envelopes?** Envelopes
  belong to the reassembly state machine (Era 1320 + 1330);
  sources are coordinator-level metadata for fan-out. Keeping them
  as parallel maps avoids polluting the envelope shape with
  coordinator concerns and lets future Eras add other side-tables
  (e.g. per-envelope reputation deltas) without changing the
  PendingEnvelope contract.
