# VECTOR III | ERA 280: The ZK-SNARK Stratum (NomosGate v2)

Цей документ формалізує перехід **NomosGate** від структурної `TypeScript`-симуляції (v1) до справжньої **Zero-Knowledge** віртуальної машини (v2) на базі SP1 (Succinct Labs) або RISC Zero. 

## 1. Концепція (Metaphysical Cryptography)

В Епоху 250+ OMEGA-64 стала справжньою розподіленою федерацією (Macro-Torus) через WebRTC Mesh. Плазміди пересуваються мережею вільно, проте це створює загрозу **Sybil/Griefing** атак: шкідлива нода може передати нескінченний рекурсивний AST (наприклад `Y I`), який спалить CPU-газ усіх worker-ів у Тору, руйнуючи фізичну тканину симуляції.

**Вирішення:** 
Кожна мутація або створення нового геному **повинна супроводжуватись криптографічним доказом коректності (STARK Proof)**. 
Замість того, щоб кожна нода самостійно перевіряла чужі плазміди, генератор (або Оракул) "згодовує" `LambdaArena` у zkVM. Згенерований proof передається разом з геномом. Сусідні ноди лише перевіряють Proof (O(1) складність) і одразу вживлюють плазму в `SharedArrayBuffer`!

## 2. Архітектура zkVM (SP1 / RISC Zero)

Ми створимо новий crate у воркспейсі: `omega_zk_guest`. 
Ця програма буде компілюватися у RISC-V і виконуватися всередині ZK Prover'а. Оскільки `omega_core` (зокрема `lambda.rs` та `phase_lattice.rs`) є повністю `no_std` сумісним і використовує лише детерміновану fixed-point математику (`Q20_SCALE`), ядро ідеально лягає на RISC-V без зовнішніх залежностей.

### The Guest Program (`omega_zk_guest/src/main.rs`)

```rust
#![no_main]
sp1_zkvm::entrypoint!(main);

use omega_core::lambda::LambdaArena;

pub fn main() {
    // 1. Зчитуємо вхідні дані (AST та початкову ентропію)
    let ast_string = sp1_zkvm::io::read::<String>();
    let entropy_seed = sp1_zkvm::io::read::<u32>();
    let max_steps = sp1_zkvm::io::read::<u32>();

    // 2. Ініціалізуємо Арену (без DOM та зовнішнього середовища)
    let mut arena = LambdaArena::new();
    
    // 3. Парсимо та перевіряємо баланс
    let root_idx = arena.parse_lambda(&ast_string);
    
    // 4. Оцінюємо життєздатність (термодинамічний ліміт Газу)
    let (mutated_idx, steps, is_timeout) = arena.evaluate_fitness_stochastic(root_idx, max_steps, entropy_seed);
    
    // Якщо мутація зависла — це "смерть", доказ не генерується (або генерується з флажком DEATH).
    assert!(!is_timeout, "NomosGate violation: Thermodynamic Gas exceeded!");

    // 5. Компілюємо морфологію в 64-бітний підпис
    let morphology = arena.compile_morphology(mutated_idx);
    let phenotype = arena.phenotype_hue(mutated_idx);

    // 6. Фіксуємо Журнал Операцій (Public Values)
    sp1_zkvm::io::commit(&(morphology, phenotype, steps));
}
```

## 3. Зміни в Мережі (WebRTCMesh)

Поточний `FOREIGN_PLASMID` пакет у `phase_network.ts` виглядає так:
```json
{
  "protocol": "OMEGA",
  "type": "FOREIGN_PLASMID",
  "data": { "ast": "S(K(I))(Y)", "energy": 255 }
}
```

Він буде модифікований для включення бінарного доказу:
```json
{
  "protocol": "OMEGA",
  "type": "FOREIGN_PLASMID",
  "data": {
    "morphology_hash": "b4633951...",
    "steps_cost": 42,
    "proof_bytes": "<base64_encoded_stark_proof>"
  }
}
```

Коли Мережа отримує пакет:
1. Викликає `sp1_verifier.verify(proof_bytes, public_values)`.
2. Якщо валідно $\rightarrow$ передає `morphology_hash` у `MessagePort` на `SharedWorker`.
3. Worker напряму вкидає код у `SharedArrayBuffer` (без витрат на парсинг `lambda.rs`!).
