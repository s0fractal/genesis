# Task 0141: Era 1550 — Auto-Investigation Loop Harness

## Status: COMPLETED | Priority: HIGH

## Context
Eras 1380→1540 each produce a layer of the autonomous-
investigation pathway. Era 1550 stitches them together with a
single `AutoInvestigationLoop` orchestrator so callers don't
have to maintain four parallel state machines.

## Objective
1. `AutoInvestigationLoop` class wrapping
   `EventChainQuorumTracker` + `QuorumInvestigationTrigger` +
   `QuorumWarrantBridge`.
2. `tick(now_ms)` walks the full chain and returns a structured
   `LoopTickResult` for HUD wiring.
3. `observePeerAnchor` + `forgetPeer` operator hooks.
4. End-to-end test demonstrating 5-peer scenario with 1
   dissenter.

## Design Notes
- **Why a single class instead of a factory function?** Tests
  need access to the three internal modules for drilldown
  assertions. A class with public readonly fields exposes them
  cleanly. Factory functions returning a closure would hide
  state behind opaque accessors.
- **Why only call `markTriggered` on emit success?** A failed
  emit means the proposal didn't reach the oracle pipeline.
  Recording it as triggered would put the cooldown gate in the
  way of a legitimate retry next tick. The current design lets
  failed emits retry on the next tick (assuming dedup window
  is shorter than retry cadence — operator-tunable).
- **Why does `forgetPeer` clear the warrant bridge's dedup
  state too?** A peer that's been formally removed from the
  mesh has no further reason to be tracked. Resetting all
  three layers ensures re-introducing the same peer_id later
  gets a fresh evaluation — no stale cooldowns blocking the
  reactor.
- **Why is `consensus_anchor === null` returned without trigger
  evaluation?** The trigger gate is "consensus.band ≥ min_band",
  but `null` consensus has band=`none`. Skipping the trigger
  call entirely shaves redundant work and makes the
  no-warrants-emitted case obvious from the tick result.
- **Why expose the bridge's `deduped_peer_ids` in the result?**
  Operator visibility. If the trigger fires for peer X but the
  warrant bridge dedupes it, the operator should see *why* no
  proposal was emitted. The `deduped_peer_ids` array carries
  exactly that diagnostic.
