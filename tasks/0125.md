# Task 0125: Era 1390 — Event Sink Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1380 stored events durably on a single relay. Era 1390
adds cross-relay convergence using the same set-difference
protocol Era 1310 uses for archives. Two relays exchange anchors,
the one with extra entries ships them as an `EventDelta`, the
receiver merges with integrity verification.

## Objective
1. `EventHashList` — initiator manifest of sorted event_hashes +
   anchor.
2. `EventDelta` — peer reply with entries the initiator lacks +
   hashes the peer lacks.
3. `applyEventDelta` — verifies schema, delta_hash, per-entry
   schema; rejects collisions; appends imports into local sink
   (fresh local chain links).
4. `eventSyncRound` — bidirectional reference convergence in one
   call.

## Acceptance Criteria

### 1. Pure Hash + List ✅
- [x] `eventHashSetHash(hashes)` — order-independent FNV-1a over
  sorted event_hash set.
- [x] Empty input → FNV-1a offset basis (`0x811C_9DC5`).
- [x] `buildEventHashList(sink, now_ms)` — sorted + anchor.

### 2. Delta Computation ✅
- [x] `computeEventDelta(initiator_list, peer_entries, now_ms)`:
  - `missing_entries` = peer entries the initiator lacks (sorted
    by event_hash).
  - `peer_missing_hashes` = initiator hashes the peer lacks
    (sorted ascending).
  - `delta_hash` = FNV-1a over missing_entries' event_hash set.
  - Identical inputs → empty delta.

### 3. Apply Delta ✅
- [x] Schema check — bad delta schema rejected.
- [x] `delta_hash` recomputation drift detection.
- [x] Per-entry schema validation against `EVENT_SINK_SCHEMA`.
- [x] Collision rejection: same `event_hash` with different `kind`
  → REJECTED (corruption, not divergence).
- [x] Idempotent on duplicate (`skipped_count` reports the count;
  no re-append).
- [x] Imports re-run `sink.append(...)` so they get fresh local
  sequence + chain_hash; `event_hash` preserved.
- [x] Returns `{ok, added_count, skipped_count, new_anchor}`.
- [x] Imported chain still passes `verifyChain()`.

### 4. Sync Round ✅

  directions; both sinks converge to identical

- [x] Disjoint inputs → both fully merge.
- [x] Identical inputs → zero additions.
- [x] Chain integrity preserved on both sides.

## Design Notes
- **Why does importing re-run `append` instead of preserving the
  source's chain_hash?** Era 1380's `chain_hash` is a log-order
  anchor. Two sinks with identical `event_hash` sets will still
  have different chain_hashes because their entries arrived in
  different orders. The cross-relay invariant we preserve is the
  *content* (event_hash); each sink owns its own ordering. Trying
  to preserve the source's chain on import would either break
  local chain verification or require operators to reason about
  multiple parallel chains — neither is worth the complexity.
- **Why reject collision on `kind` mismatch but only spot-check
  payload via type-equality?** `kind` is the discriminator that
  defines the payload's shape and semantics; mismatched `kind` at
  the same hash is unambiguous corruption. Deep payload-equality
  is expensive (JSON.stringify in a hot loop) and the
  `event_hash` itself is computed from the payload semantics by
  the originating Era — if those two Eras agree on the hash but
  disagree on the kind, the source of disagreement is structural,
  not just byte-jitter. Accepting the kind check as the bright
  line keeps the merge fast while still catching the problematic
  case.
- **Why mirror Era 1310 instead of generalizing?** A premature
  generic abstraction over "content-addressed set sync" would
  pile constraints onto two different types (ArchivedVerdict
  shape vs ForensicEvent shape) that are unlikely to share more
  evolution than they already do. The two sync modules are 200-
  line peers; cross-cutting abstraction costs more than it saves
  at this scale. If a *third* such store appears (Era 1400+),
  abstraction becomes worth doing.
