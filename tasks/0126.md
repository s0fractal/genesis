# Task 0126: Era 1400 — Cortex-M4F Forensic Spore Bring-up (Rust Mirror)

## Status: COMPLETED | Priority: HIGH

## Context
Eras 1380–1390 added a chain-anchored forensic event log with
cross-relay sync. Both layers were JS-only. Era 1400 ports the
minimal subset onto the bare-metal `omega_v2` substrate so a
Cortex-M4F spore can hold its own log + reconcile with relays
using identical hash semantics.

## Objective
1. `no_std`-clean Rust port of `ForensicEventSink` with
   compile-time capacity (const-generic `N`).
2. Byte-for-byte parity on `compute_chain_hash` and
   `event_chain_anchor` with the JS implementation.
3. Locked cross-substrate test vectors pinned in BOTH suites.

## Design Notes
- **Why `MAX_ANCHOR_HASHES = 64` const cap instead of `4*N`?**
  Const generics in stable Rust don't allow expressions like
  `4*N` in array sizes. Const-cap workaround keeps the code
  buildable on stable while still serving every realistic spore
  scenario (typical sinks hold a few dozen events). If a future
  use case needs larger anchors, a streaming variant (chunked
  FNV-1a) can be added without changing the API.
- **Why insertion sort and not `slice::sort`?** Slice sort
  requires `alloc` for some paths and pulls in `core::slice`
  comparators that bloat the Cortex-M4F binary. Insertion sort
  on N≤64 is trivial, branch-predictable, and verifiably correct
  with two nested loops — perfect for resource-constrained
  targets.
- **Why store `kind` inline (`[u8; 16]`) instead of by reference?**
  Bare-metal nodes don't have a heap. Inline storage of a
  bounded-length buffer is the standard pattern in `no_std`
  data structures. Callers using kinds longer than 16 bytes are
  silently truncated — but our protocol's kinds are short tags
  ("alarm", "verdict") well under the cap.
- **Why null-byte kind delimiter in chain hash?** Without a
  delimiter, "alarm" + "0x42" hashes the same as "ala" + "rm" +
  "0x42" prefix-extension attack on FNV. The null byte breaks
  the prefix ambiguity. JS uses the same convention; the Rust
  port matches it byte-for-byte.
- **Why locked test vectors instead of just running Rust+JS
  side-by-side?** Locked hex values catch divergence even if
  only one side's test suite is run. They're also cheap CI
  signals — operators see a specific anchor mismatch instead of
  "tests don't agree" with no clear culprit.
