# Task 0137: Era 1510 — Mesh Event Bridge Adapter

## Status: COMPLETED | Priority: HIGH

## Context
Era 1500 produced the transport-agnostic `WebRTCEventBridge`.
Era 1510 adapts it onto the existing `WebRTCV2Mesh`'s plasmid
pipeline so browser peers can run forensic-event convergence on
the same mesh that already carries warrants, votes, and
resilience data.

## Objective
1. `MeshBridgeTransport` adapter wrapping `BridgeTransport` over
   a per-peer plasmid emit callback.
2. `'EVENT_SYNC'` semanticType + `eventSyncBody`/`eventSyncTarget`
   additions to `PlasmidPayload`.
3. `decodeMeshPayload` helper for receiver-side BridgeMessage
   recovery.
4. End-to-end test through the adapter.

## Design Notes
- **Why a separate adapter module instead of extending the
  bridge?** Layering. Era 1500's `WebRTCEventBridge` knows
  nothing about plasmids, mesh peer IDs, or WebRTC. Adding
  mesh-specific code there would couple two concerns. The
  adapter pattern keeps Era 1500 portable to non-mesh
  transports.
- **Why does `MeshBridgeTransport` accept a callback rather
  than a `WebRTCV2Mesh` instance?** Tests can run without
  instantiating real RTCPeerConnections — the callback can be
  a synchronous fake. Production code wires the callback to
  `mesh.enqueuePlasmid` or to per-peer `channel.send`.
- **Why optional plasmid fields rather than a separate
  `EventSyncPlasmid` type?** Backward compatibility. Existing
  consumers of `PlasmidPayload` ignore the new fields; new
  consumers gate on `semanticType === 'EVENT_SYNC'` before
  reading them. A separate type would force a discriminated
  union that ripples through every plasmid handler.
- **Why is `decodeMeshPayload` lenient (returns `null` instead
  of throwing)?** Mesh receivers process untrusted input.
  Throwing on every malformed plasmid would crash dispatch
  loops. Returning `null` lets the receiver log + skip.
- **Why is the V2_SYNC dispatch wiring deferred to Era 1520?**
  Modifying the mesh's existing handler requires careful
  thought about attractor zones, hop counts, and routing.
  Era 1510 publishes the contract (adapter + types); Era 1520
  consumes it. Splitting the work makes each Era reviewable
  in isolation.
