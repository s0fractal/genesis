## Загальна оцінка

Концепція справді унікальна і амбітна — WebGPU ping-pong буфери + Rust WASM
SIMD + семантичне ін'єкування плазмід через FNV-1a. Архітектурний фундамент
тримається. Але є конкретні проблеми, які роблять кодбазу важчою ніж вона мусить
бути.

## Критичні проблеми

### 1. LUT-и — найбільший злочин проти компактності

`SINE_LUT` (~2000 рядків чисел), `ENTROPY_LUT`, `ATAN_LUT` — це ~3500 рядків з
7500 у файлі. **Майже половина кодбази — захардкоджені числа.**

```rust
// ❌ Зараз: 500 рядків літералів
pub const SINE_LUT: [i32; 256] = [0, 25, 50, 75, ...];

// ✅ Треба: генерувати при компіляції
pub const SINE_LUT: [i32; 256] = {
    let mut lut = [0i32; 256];
    let mut i = 0usize;
    while i < 256 {
        // const fn не має f64::sin, тому або proc-macro,
        // або build.rs генерує lut.bin → include_bytes!()
        i += 1;
    }
    lut
};
```

Найкраще рішення — `build.rs` генерує `lut.bin` → `include_bytes!("lut.bin")`.
Файл стає 50 рядків замість 2500.

### 2. Дублювання в WGSL шейдерах

`compute_simulate.wgsl` і `compute_apply.wgsl` обидва оголошують
`struct Mutation`. При будь-якій зміні — треба правити двічі.

```wgsl
// ❌ Дублюється в двох файлах
struct Mutation { phaseShift: i32, amplitude: i32 };
```

→ Винести в `common.wgsl` і підключати через `include` (або WGSL preprocessor у
Vite).

### 7. Невідповідність версій

`package.json` → `42.0.0`, `omega_core/Cargo.toml` → `10.0.0`. Скрипт експорту
читає версію з `package.json` і будує заголовок "ONTOLOGY 42". Rust-крейт живе у
своєму часі. Треба або синхронізувати, або зробити версію крейта незалежною і
явно не виводити її як "ontology number".

### 9. `processQueue` — прямий DOM-доступ з Oracle

```typescript
// ❌ Oracle напряму маніпулює DOM
const debugImg = document.getElementById(
  "oracle-debug-vision",
) as HTMLImageElement;
if (debugImg && structuralImage) {
  debugImg.style.display = "block";
  debugImg.src = "data:image/png;base64," + structuralImage;
}
```

Oracle не повинен знати про DOM. Треба або callback, або EventEmitter:

```typescript
// ✅ Oracle emits, bootstrap wires
oracle.on("vision", (base64) => {
  DOM.oracleDebugVision && Object.assign(DOM.oracleDebugVision, {
    style: { display: "block" },
    src: `data:image/png;base64,${base64}`,
  });
});
```

## Якщо рефакторити — пріоритети

1. **`build.rs` для LUT** → `-3000 рядків` з проекту відразу
2. **`decomposeHash`** → усуне дублювання в `phase_compute.ts`
3. **WGSL `override` константи** → читабельність шейдерів +50%
4. **Видалити мертвий код** в `replay.ts`
5. **DOM decoupling Oracle** → правильна архітектура

Загальна структура — добра. Ідея — сильна. Але LUT-и захаращують все і дають
хибне відчуття "великого проекту". Без них — це компактна і елегантна система.
