# Task 0103: Era 1170 — Path Diversification

## Status: COMPLETED | Priority: HIGH

## Context
Era 1160 selects the single best path. But for high-stakes frames
(WARRANT_VOTE — the things that change Senate state), single-path
delivery has a single point of failure: any radio glitch on that
chain drops the vote. Era 1170 introduces redundancy that's
proportional to importance.

## Objective
For high-priority frames, send the SAME intent along TWO disjoint
paths simultaneously, then deduplicate at the destination so the
Senate never sees double votes. HEARTBEATs (low priority) stay
single-path — duplicating them would waste mesh radio time.

## Design Notes
- **Why FNV-1a over (type, oracle_bit, target, tick)?** These four
  bytes uniquely identify the intent. TTL and trail digest legitimately
  differ across path copies; CRC differs per-routing-mutation.
  Including those in the dedup key would defeat the duplication.
- **Why not just compare full frame bytes?** Two valid copies of the
  same WARRANT_VOTE will have different `payload_b` (trail), so a
  byte-equality dedup would fail. The dedup key extracts only the
  semantically-meaningful portion.
- **DedupWindow is FIFO, not LRU.** A FIFO bound is sufficient because
  duplicates arrive within hops of each other (max 16 TTL × radio
  time ≈ ms). Any frame whose duplicate hasn't arrived within the
  window is either lost or single-pathed; no need to keep older keys.
- **The originator picks paths; the destination dedups.** Neither
  side needs to know about the other beyond the dedup key contract.
  This keeps the layers independent.
