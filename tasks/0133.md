# Task 0133: Era 1470 — Hash-List Request/Response Frames

## Status: COMPLETED | Priority: HIGH

## Context
Era 1460's convergence driver shipped the full local set on
mismatch. Era 1470 adds request/response frames so a spore can
ask for the peer's hash list and ship only the precise
difference.

## Objective
1. Reserve `FRAME_TYPE_EVENT_HASH_REQUEST = 11` and
   `FRAME_TYPE_EVENT_HASH_RESPONSE = 12` in BOTH Rust and JS.
2. Rust frame builders for both types.
3. JS chunker/reassembler for chunked response (4 hashes per
   frame).
4. `computeMissingFromPeer` set-difference helper.

## Design Notes
- **Why 4 hashes per chunk?** Frame has 4 u32 payload slots
  (proposal + 3 payloads). One u32 reserved for seq/total/valid
  packing. tick reserved for request_id. That's the maximum
  density given the 32-byte frame.
- **Why u8 seq + u8 total instead of u16/u16?** Practical sink
  sizes are well under 1024 hashes (255 × 4). u8 leaves room
  in `reserved` for the `valid` byte without contortions. If a
  future use case needs >1020 hashes, a streaming variant can
  be introduced without breaking this Era.
- **Why include `valid` per chunk?** A list of 5 hashes → 2
  chunks where the second has only 1 valid hash. Without
  `valid`, the receiver can't distinguish a hash of value 0
  from an unused slot. The hash 0 is technically valid for FNV
  output; protocol must allow it. `valid` removes the
  ambiguity.
- **Why does empty list still produce 1 chunk?** A spore that
  wants to advertise "I know nothing" should be able to do so
  unambiguously. Sending 0 chunks would be indistinguishable
  from "no response at all" or "lost in transit". 1 chunk with
  `valid=0` is a positive "answered, nothing to share".
- **Why `computeMissingFromPeer` is generic over `T extends
  {event_hash: number}`?** Both `ArchivedVerdict` (Era 1300)
  and `ForensicEvent` (Era 1380) carry `event_hash`. Future
  Eras may add more types. A generic helper avoids per-type
  duplication.
