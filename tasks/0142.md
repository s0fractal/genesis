# Task 0142: Era 1560 — Quarantine-Aware Exclusion

## Status: COMPLETED | Priority: HIGH

## Context
Era 1550 closes the autonomous loop ending in quarantine. But
after quarantine engages, the convergence stack still tracks
the bad peer's anchor observations. Era 1560 propagates the
quarantine state into the quorum tracker and investigation
loop so excluded peers stop influencing consensus.

## Objective
1. Add `exclude`/`unexclude`/`excludedPeers` to
   `EventChainQuorumTracker`.
2. Excluded peers: existing observations dropped immediately;
   subsequent `observe` calls silently ignored.
3. Add `excludePeer`/`includePeer` to `AutoInvestigationLoop`
   with appropriate cascading state cleanup.
4. Tests covering tracker + loop behavior.

## Acceptance Criteria

## Design Notes
- **Why preserve warrant bridge dedup state across exclusion?**
  Quarantine is "verified bad actor", not "temporary pause".
  When a peer is un-quarantined and immediately re-dissents,
  the cooldown was put in place to protect the warrant
  pipeline; that protection should outlive the quarantine
  toggle. If operators want to flush the cooldown too, they
  can call `loop.warrants.forget(peer_id)` explicitly.
- **Why does `excludePeer` call `trigger.forget` but not
  `bridge.forget`?** Trigger state tracks ongoing investigation
  duration. Holding it through quarantine would make the next
  un-exclude immediately fire (duration already long) — wrong
  semantics, since the peer is fundamentally a different
  participant after quarantine resolution. Resetting the
  trigger record means the next dissent gets fresh
  duration tracking. Bridge dedup is the bandwidth gate, not
  the investigation-duration gate, so it's preserved.
- **Why is exclusion at the tracker layer instead of the
  trigger layer?** Two reasons. First, the tracker is the
  ground-truth source for "who said what about the chain"; if
  excluded peers' observations leaked through to the trigger,
  they could still appear as dissenters and affect the
  band calculation. Second, the tracker is reused by other
  consumers (HUD, telemetry); a single source-of-truth
  exclusion serves all downstream readers.
- **Why use a Set for excluded peers instead of a flag in
  the observation record?** The Set persists across
  observation drops/refreshes — a peer marked excluded stays
  excluded even if observations are evicted by TTL.
- **Why no time-bounded exclusion?** Quarantine is governed
  by Era 1080's separate state machine; the tracker
  shouldn't duplicate that lifecycle. When the senate decides
  to lift quarantine, it calls `includePeer`. Adding a TTL
  here would create two clocks for one semantic.
