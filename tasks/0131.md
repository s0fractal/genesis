# Task 0131: Era 1450 — Spore Main-Loop Glue + Wire-Driver Hook

## Status: COMPLETED | Priority: HIGH

## Context
Eras 1400-1440 produced every primitive a spore needs to
participate in event convergence. What was missing: the glue that
runs them in a tick loop driven by real RX/TX bytes. Era 1450
lands that glue with a clean `WireDriver` abstraction so any
host (UART, SPI, BLE, in-process loopback) can plug in.

## Objective
1. `WireDriver` trait — non-blocking `read` / `write` with
   byte-count semantics.
2. `SporeRunner<N, C>` — generic main loop holding sink +
   accumulator + diagnostics.
3. Magic-byte resync logic so the runner recovers from cold-boot
   or wire glitches without operator intervention.
4. `LoopbackDriver` impl + paired-runner test proving end-to-end
   convergence over an actual byte stream.

## Acceptance Criteria

### 1. Wire Driver ✅
- [x] `WireDriver::read(&mut self, buf: &mut [u8]) -> usize` —
  non-blocking, returns byte count.
- [x] `WireDriver::write(&mut self, buf: &[u8]) -> usize` —
  non-blocking, returns bytes accepted.
- [x] `LoopbackDriver` for in-process testing with `deliver` API.

### 2. SporeRunner ✅
- [x] `new(self_relay_id, broadcast_interval_ticks)` const ctor.
- [x] `step(&mut self, driver, now_ms)` does:
  - Drain RX → 64-byte staging buffer.
  - Magic-byte resync on garbage.
  - Parse complete 32-byte frames.
  - Route by frame_type:
    - `EVENT_HASH_LIST` → record peer anchor.
    - `EVENT_DELTA_CHUNK` → feed accumulator; on complete,
      take_delta + apply_event_delta.
    - Others → silently ignored.
  - Periodic broadcast of own hash-list (per
    `broadcast_interval_ticks`).
- [x] `observe_local_event(kind, hash, now_ms)` injects a local
  event into the sink.
- [x] `ship_delta(driver, entries, peer_anchor, now_ms)` builds a
  chunked envelope + writes to driver.
- [x] Diagnostics: `frames_received`, `frames_applied`,
  `envelopes_completed`, `apply_collisions`.

### 3. Tests ✅
- [x] `loopback_driver_round_trips` — basic deliver + read + drain.

  hash-list + delta exchange via PairedDriver.

## Design Notes
- **Why a 64-byte staging buffer (2 frames)?** Worst case: a
  partial frame at the head + a complete frame following.
  Holding 2 frames worth lets the parser process one at a time
  without losing bytes. Larger buffers waste SRAM; smaller ones
  cause RX drops on bursty links.
- **Why magic-byte resync instead of length-prefix framing?**
  A length-prefix scheme requires reading the length first before
  knowing the frame size — adds state machine complexity. Fixed-
  size 32-byte frames + magic-byte resync is simpler: any bytes
  outside a frame boundary are skipped until the next magic byte
  appears. Loss of a single byte in the middle of a frame still
  corrupts that frame (CRC catches it) but recovery is the next
  magic byte ahead.
- **Why does `step` automatically `take_delta + apply` instead of
  letting the caller do it?** This is the runner's job — it
  abstracts the protocol so callers see only `observe_local_event`
  and step ticks. Higher-Era drivers that want to intercept
  (e.g. for set-difference computation between accumulate and
  apply) can subclass / wrap.
- **Why `LoopbackDriver` doesn't auto-deliver TX to a peer?** No
  way to express the cross-borrow safely without `unsafe` or
  `Rc<RefCell<>>` (which we can't use in `no_std`). The test
  uses a `PairedDriver` pattern with explicit `deliver_to_peer`
  to make the wiring obvious — this is also closer to how a real
  UART works (TX is independently buffered on the wire before
  RX picks it up).
- **Why diagnostics counters wrap rather than saturate?**
  Operator counters are typically read modulo a window for
  rate calculations — saturation at u32::MAX would break those
  rates after ~50 days. Wrapping with documented semantics is
  the standard for embedded counters.

The runner now records `last_peer_anchor` but doesn't act on it.
When the runner observes `peer_anchor != self.anchor()`, the
next Era's logic should:
- Maintain a fixed `[PeerInfo; M]` table of peers seen.
- For each peer with anchor mismatch + scheduler-allowed, call
  `ship_delta` with the entries the peer is missing.
- Computing the set-difference requires the peer's full
  digest list — Era 1460 will add a new
  `EVENT_HASH_REQUEST`/`EVENT_HASH_RESPONSE` frame pair so the
  spore can ask "send me your full hash list" before computing
  the diff.
