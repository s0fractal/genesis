# Task 0149: Era 1630 — Translation-Aware Sink Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1620 introduced explicit schema translators, but Era 1600's
schema-validated apply path still refused every major mismatch.
That left migration windows half-open: operators could register a
translator, but sync could not use it.

## Objective
1. Wire `SchemaTranslatorRegistry` into `applyEventDeltaWithSchema`.
2. Preserve Era 1600's default refusal when no registry/pair exists.
3. Translate `missing_entries`, recompute `delta_hash`, then delegate
   to Era 1390 unchanged.
4. Let `SchemaAwareSinkSync` answer translatable peers, not only
   same-major compatible peers.

## Acceptance Criteria

### 1. Default Firewall Preserved ✅
- [x] `applyEventDeltaWithSchema(..., no_registry)` still returns
  `major-mismatch` for incompatible majors.
- [x] Name mismatches still refuse before translation lookup.

### 2. Translation Apply Path ✅
- [x] Registered sender→local translator runs over
  `delta.missing_entries`.
- [x] Translated deltas recompute `delta_hash` before reaching
  `applyEventDelta`.
- [x] Translator `null` drops are accepted as a verified no-op when
  the resulting hash set is empty.
- [x] Era 1390 still owns collision/schema/hash validation after
  translation.

### 3. Diagnostics ✅
- [x] Successful translated applies expose optional
  `translated_count` and `dropped_count`.
- [x] Underlying apply failures still surface as `apply-failed`.

### 4. SchemaAwareSinkSync ✅
- [x] Constructor accepts an optional `SchemaTranslatorRegistry`.
- [x] `computeDeltaForPeer` returns a delta for major mismatches only
  when a local→peer translator is registered.
- [x] `apply` passes the registry into the apply path.

### 5. Tests ✅
- [x] Major mismatch still refuses without registry.
- [x] Major mismatch with registered translator applies.
- [x] Translator drop path is deterministic and verified.
- [x] `SchemaAwareSinkSync` can compute and apply translated deltas.
- [x] Existing Era 1600 same-major and rejection tests remain green.

## Design Notes
- **Why optional registry instead of global state?** Translation is an
  operator declaration, not a protocol default. Passing the registry
  keeps the schema firewall explicit at each boundary.
- **Why recompute `delta_hash` after translation?** Translators may
  preserve event hashes, rewrite them, or drop events. The receiver
  must verify the exact payload it is about to apply.
- **Why keep `SCHEMA_SYNC_SCHEMA = OMEGA-1600/v1`?** The wire wrapper
  did not change. Era 1630 is an additive local capability on the
  apply/orchestration path.
