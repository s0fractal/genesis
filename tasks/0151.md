# Task 0151: Era 1650 — Translation Policy Digest & Drift Alarm

## Status: COMPLETED | Priority: HIGH

## Context
Era 1640 made translation policy usable by the multi-sink operator
layer, but the policy itself was still local state. Two peers could
both support schema translation while disagreeing about which
source→target migration pairs were authorized.

## Objective
1. Canonicalize registered translator pairs.
2. Compute deterministic policy digests.
3. Build compact peer policy claims.
4. Detect peer policy drift before translated sync runs.
5. Sink forensic events for translation authorization disagreement.

## Acceptance Criteria

### 1. Deterministic Policy Digest ✅
- [x] Empty policy hashes to FNV-1a offset basis.
- [x] Pair order does not affect the digest.
- [x] Registry digests are derived from `SchemaTranslatorRegistry.listPairs()`.

### 2. Broadcastable Claim Shape ✅
- [x] `buildTranslationPolicyClaim(peer_id, registry, now_ms)` returns
  schema, peer id, policy hash, pair count, canonical pairs, and timestamp.
- [x] Claims use `TRANSLATION_POLICY_SCHEMA = OMEGA-1650/v1`.

### 3. Drift Detection ✅
- [x] Matching peer policy produces no alarm.
- [x] Mismatched hash or pair count marks the peer as drifted.
- [x] Repeated identical drift from the same peer is deduplicated.
- [x] A changed peer policy hash raises a fresh alarm.

### 4. Bounded Monitor ✅
- [x] Peer observations have TTL eviction.
- [x] Monitor capacity evicts oldest peers deterministically.
- [x] Summary exposes local policy hash, pair count, observed peer count,
  drift peer count, and alarm count.

### 5. Forensic Event ✅
- [x] Drift event hash is deterministic.
- [x] Optional `ForensicEventSink` receives
  `translation-policy-drift` entries automatically.
- [x] Callback path receives the same alarm.

## Design Notes
- **Why hash only source→target pair keys?** The registry stores
  executable translator functions, which cannot be serialized or hashed
  deterministically across runtimes. The policy digest anchors the
  authorization surface: which migrations are allowed.
- **Why not decide consensus here?** Era 1650 is an observability layer.
  It records disagreement; existing quorum/investigation machinery can
  decide what to do with the forensic event.
- **Why include pair_count when hash is present?** It gives operators a
  cheap diagnostic in summaries and catches malformed claims that reuse
  a stale hash with inconsistent metadata.
