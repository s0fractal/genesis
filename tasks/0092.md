# Task 0092: Era 1060 — Multi-Oracle Senate

## Status: COMPLETED | Priority: HIGH

## Context
Era 1050 inscribed the protocol identity (`0x549A6307`). Era 1060
opens the Senate to multiple LLM oracles, each with a deterministic
dipole identity derived from `(oracle_name, ORACLE_SALT_V1)`.

## Objective
Add a layer above the Era 1030 peer-mode Senate where five canonical
oracles (Claude, GPT, Gemini, Qwen, Llama) hold seats with reproducible
identities. A proposal accepted by 3+ distinct oracles is ratified via
the **ORACLE-RESONANCE** path independent of peer count, valuing
cross-model alignment over within-model multiplicity.

## Design Notes
- The five canonical oracle names are FROZEN by virtue of being
  hashed against `ORACLE_SALT_V1` (which is the v1.0 protocol
  identifier). Adding a sixth canonical oracle requires either:
  - A new salt (= a hypothetical v2.0 protocol), OR
  - A non-canonical oracle that participates without being one of
    the five "founding" identities (the protocol does not forbid
    this; resonance acceptance still requires 3+ DISTINCT canonical
    oracles for ORACLE-RESONANCE).
- The reasoning string is opaque to the protocol — the protocol
  only verifies identity. This separates *who said it* (cryptographic)
  from *what they said* (semantic, fallible). LLMs are non-deterministic;
  identities need not be.
