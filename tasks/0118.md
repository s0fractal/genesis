# Task 0118: Era 1320 — Archive Sync over SporeFrame Wire

## Status: COMPLETED | Priority: HIGH

## Context
Era 1310 defined a pure, transport-agnostic delta-exchange protocol
(`computeDelta`, `applyDelta`, `syncRound`). The records inside an
`ArchiveDelta` are larger than 32 bytes, so they cannot fit in a
single SporeFrame. Era 1320 wires Era 1310 onto the wire by
introducing a "delta envelope" — a sequence of `DELTA_CHUNK` frames
sharing an `envelope_hash`.

## Objective
Provide pure functions for chunking and reassembly:
1. `chunkDelta(delta, sender_relay_id)` → `SporeFrame[]` (1 header
   + N record chunks).
2. `reassembleDelta(frames, expected_envelope_hash?)` →
   `{ok, delta?, missing_sequences, error?}`.

Out-of-order arrival, retransmission, and missing-chunk gaps must
all be tolerated/detected without state outside the function.

## Design Notes
- **Why a header frame instead of packing metadata into record
  frames?** The reassembler needs to know `total` before it can
  decide whether the envelope is complete. With a header at
  sequence=0 carrying `total` (and validated against every record
  frame's `total` field), the receiver can detect a mismatched
  envelope as soon as it sees the first record. Packing metadata
  into every record frame would waste bytes; packing it nowhere
  would make incomplete-envelope detection ambiguous.
- **Why is the wire form lossy on adjudicator lists and timestamps?**
  Bandwidth. The fields the receiver actually uses for
  Era 1310's `applyDelta` integrity check are digest, verdict,
  replayed_q16. Everything else is auxiliary metadata that can
  be re-derived (or fetched separately) if a forensic deep-dive
  is needed. The archive ND-JSON (Era 1300) remains the source
  of truth for full-fidelity records.
- **Why include `total` in every record frame instead of header
  only?** Defense in depth. If the header arrives corrupted (bad
  CRC → frame discarded), record frames with consistent `total`
  values can still detect when the envelope is structurally
  malformed — the reassembler refuses to proceed without an
  authoritative header, but the consistency check across record
  frames adds a corruption-detection layer.
- **Why omit `peer_missing_digests` from the wire envelope?**
  In Era 1310, `peer_missing_digests` was a bandwidth optimization
  for the *symmetric* delta-exchange direction. Over the wire,
  the symmetric direction is a separate envelope (sender + receiver
  swap roles), so each side can compute its own peer_missing list
  by intersecting its own digest set with the freshly received
  records. Sending the list redundantly would waste a frame.
- **Why a single `oracleBit` byte for sender ID instead of a full
  u32?** The frame already has `payloadA` for full sender_relay_id
  in record frames, but the header reuses payloadA for
  `initiator_digest_set_hash`. The low-byte `oracleBit` field is
  enough for casual sender-pinning; full provenance lives in
  the per-record `source_relay_id`.

## Next Era Trigger
**Era 1330: Sync Scheduler + Retransmission Driver.** Era 1320 is
synchronous — caller chunks an entire delta and ships every frame
in a tight loop. Production needs a periodic scheduler that decides
*when* to initiate a sync (e.g. on partition resolve, on archive
checkpoint, on idle timer) plus a retransmission driver that
consumes `reassembleDelta`'s `missing_sequences` to issue targeted
retransmit requests with bounded backoff and a give-up horizon —
similar to Era 1170's path diversification but specialized for
delta envelopes rather than singular high-priority frames.
