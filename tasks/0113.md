# Task 0113: Era 1270 — Cross-Substrate Trace Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1260 made each relay's frame log archivable + replayable. But
each relay only sees frames that physically reached it. Two relays
observing overlapping mesh segments hold partially-overlapping
logs. Era 1270 defines the merge protocol so cooperative relays can
combine their viewpoints into a more complete forensic
reconstruction.

## Objective
Provide deterministic merge functions over frame log slices that
dedup identical observations and preserve ordering by
`received_at_ms`. The merged log replays through any observer to
yield a strictly-≥ outcome compared to either input log alone.

## Acceptance Criteria

### 1. Trace Sync Module ✅
- [x] `src/network/trace_sync.ts`:
  - `observationHash(rec)` — FNV-1a over (frame_bytes,
    delivered_by, received_at_ms). Same observation = same hash.
  - `mergeTraces(a, b)` returns
    `{merged, shared_hashes, a_only, b_only}`.
  - `mergeMany(recorders[])` — pairwise merge of N recorders.
  - `recorderFromMerge(result, capacity?)` — builds a fresh
    FrameRecorder from a merge result for direct replay.
  - `coverageStats(result)` — overlap_ratio +
    a/b_exclusive_ratio for HUDs.

### 2. Determinism ✅
- [x] `mergeTraces(a, b)` and `mergeTraces(a, b)` (called twice)
  produce byte-identical merged sequences.
- [x] Sort key: `received_at_ms` ascending → observation_hash
  ascending tiebreak.
- [x] Order is stable even when timestamps coincide.

### 3. Dedup Semantics ✅
- [x] Same frame + same `delivered_by` + same timestamp →
  one observation (idempotent).
- [x] Same frame + different `delivered_by` → two observations
  (relay-A saw it AND relay-B saw it; both are forensically
  meaningful).
- [x] Same frame + same deliverer + different timestamp → two
  observations (sequential).

### 4. Forensic Invariant ✅
- [x] Test "merged replay ≥ each individual replay": construct
  two recorders with overlapping intent sets, merge them, replay
  through ConvergenceDetector. The merged detector sees the
  union of intents (more total) AND correctly classifies
  cross-relay overlapping intents as double-witness.

### 5. Tests ✅
- [x] 19 Deno tests cover: hash determinism, hash sensitivity to
  each input, disjoint merge, identical observation dedup,
  same-frame-different-relay = 2 records, sort-by-timestamp,
  determinism across calls, hash tie-break, empty input
  handling, coverage stats, recorderFromMerge replay
  reconstruction, capacity respect, forensic invariant
  (merged total > individual totals).

## Design Notes
- **Why hash includes `delivered_by`?** A frame physically
  observed by relay-A vs relay-B is two distinct forensic
  events even if the wire bytes are identical. Excluding
  `delivered_by` from the hash would treat them as one and
  lose the multi-perspective signal that's the whole point of
  Era 1270.
- **Why hash includes `received_at_ms`?** Same relay observing
  the same wire frame at two different times means the frame
  was duplicated (legitimate Era 1170 path diversification).
  Forensic timeline care about that.
- **Why sort by `received_at_ms` first?** Replays through
  ConvergenceDetector and similar layers are time-aware. The
  output observer's state is the same as if frames had been
  ingested in chronological order — even when sourced from
  multiple recorders.
- **Why does `mergeMany` use pairwise reduction?** O(N) total
  comparisons across N recorders. Could be batched into a
  single pass with all hashes seen, but pairwise is more
  observably-correct and the tests verify equivalence.
- **The merge is COMMUTATIVE in semantics, not in shared_hashes
  attribution.** `mergeTraces(a, b).a_only` and
  `mergeTraces(b, a).b_only` are identical sets. Tests
  exercise both forms.
