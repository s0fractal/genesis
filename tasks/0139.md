# Task 0139: Era 1530 — Quorum-Driven Investigation Trigger

## Status: COMPLETED | Priority: HIGH

## Context
Era 1520 reports cross-relay anchor disagreement. Era 1530
turns the dissenter list into an actionable trigger: peers
warranting forensic investigation, gated on band threshold,
dissent duration, and per-peer cooldown.

## Objective
1. `QuorumInvestigationTrigger` class with per-peer
   `DissenterRecord` state.
2. `evaluate(snapshot, now_ms) → TriggerOutcome` with
   `{fire_now, pending, dissenter_count}`.
3. `markTriggered(peer_id, now_ms)` for cooldown
   enforcement.
4. Convenience `tickTrigger(tracker, trig, now_ms)` orchestrator.

## Acceptance Criteria

### 1. Trigger Class ✅
- [x] Constructor validates `per_peer_cooldown_ms > 0` and
  `min_dissent_duration_ms ≥ 0`.
- [x] `evaluate(snap, now_ms)` returns `TriggerOutcome` with
  three gates: band, duration, cooldown.
- [x] `markTriggered` updates cooldown anchor.
- [x] `forget` drops a record explicitly.
- [x] `records_snapshot` returns sorted-by-peer_id state.

### 2. Gates ✅
- [x] Band gate: snapshot.band must be ≥ opts.min_band
  (ordering: none < lone < double < triple+ < high).
- [x] Duration gate: `now - first_seen_dissenting ≥
  min_dissent_duration_ms`.
- [x] Cooldown gate: `now - last_triggered ≥ per_peer_cooldown_ms`.
- [x] All three must pass for fire_now; otherwise pending.

### 3. State Lifecycle ✅
- [x] First sighting of dissenter → record created with
  `first_seen_dissenting_ms = now`.
- [x] Resolved dissenter (joins consensus) → record dropped.
- [x] Consensus change → first_seen_dissenting reset (avoids
  unfair count against new consensus); cooldown preserved.

### 4. Convenience ✅
- [x] `tickTrigger(tracker, trigger, now_ms)` — pulls snapshot
  from tracker, calls evaluate.

### 5. Tests ✅

  cooldown elapsed re-fires, empty consensus no fire, dissenter

  creates record if missing, consensus change preserves cooldown,

## Design Notes
- **Why three separate gates instead of a single combined
  predicate?** Each gate has an independent meaning: band is
  network-level confidence, duration is "rule out transient
  lag", cooldown is "don't spam the warrant pipeline".
  Separating them lets operators tune each independently.
- **Why does `evaluate` mutate internal state?** The trigger is
  inherently stateful — it tracks first-seen-dissenting per peer
  to enforce duration. Pure-functional approach would require
  the caller to manage state externally, which defeats the
  purpose of a trigger module. The mutation is contained to
  `records` and `last_consensus`.
- **Why preserve `last_triggered_ms` across consensus changes?**
  A peer just investigated shouldn't be re-investigated if the
  consensus shifts and it's still dissenting on a different
  anchor. The cooldown is about pacing the warrant pipeline,
  not about what specifically is being disagreed upon.
- **Why does `markTriggered` create a record if absent?** Race
  condition tolerance. A caller might issue a warrant before
  the next `evaluate` call has refreshed records. Letting
  `markTriggered` create the record avoids a bug class where
  cooldown is silently ignored.
- **Why `min_band: "triple+"` as default?** Conservative.
  Investigating dissenters on a 2-vs-1 split would be
  premature — the "majority" might not even be majority once
  more peers report. ≥3 observers in agreement is the
  triple-corroboration threshold from Era 1220, reused here.
- **Why are dissenter anchors not faithfully tracked per-peer?**
  The `QuorumResult` snapshot doesn't surface per-peer anchors;
  it just lists dissenter peer_ids. Era 1520 could be extended
  to return them, but the trigger semantics don't need
  per-peer anchor data — only "is this peer dissenting?". Future
  Eras requiring fine-grained anchor info can plumb it through.
