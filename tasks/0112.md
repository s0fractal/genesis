# Task 0112: Era 1260 — Snapshot/Trace Replay

## Status: COMPLETED | Priority: HIGH

## Context
Every observability layer (Era 1180 ConvergenceDetector,
Era 1200 PeerSnapshotMonitor, Era 1220 InvestigationConvergenceTracker,
Era 1240 mesh_health, Era 1250 CompositeHealthMonitor) is a pure
function of the frames it observed. If we keep an append-only
log of every frame, we can replay any past window through the
SAME pure functions and forensically reconstruct what the relay
knew at any point in time.

## Objective
Provide a `FrameRecorder` (bounded ring buffer of incoming frames)
and replay helpers that re-feed any window of recorded frames
through arbitrary observation functions. The invariant:
**replay(frames) === observe-each-frame-once(frames)**.

## Design Notes
- **Why shallow-copy frames on record?** SporeFrame fields are
  primitive numbers, so shallow copy is sufficient. A deep
  clone would just be wasted work — the only mutable subfield
  is the (rarely-needed) crc32 which is set at construction.
- **Why default capacity 4096?** ~1 hour of 1Hz traffic per
  spore, the typical incident-investigation window. Operators
  who need longer windows configure `capacity` higher; relays
  on 4MB ESP32 flash should tune to 1024 or less.
- **Why support `serialize()` / `fromSerialized()`?** Forensic
  archives. An operator can dump a recorder's full state to
  disk and replay it later in a controlled environment with
  arbitrary `replayThrough` analyses — without the original
  relay still running.
- **Why does deserialize lose `delivered_by` metadata?** That
  field isn't on the wire (it's the receiver's annotation).
  Replays mark restored frames with `(replay)` to make this
  explicit; downstream analytics that care about delivery
  source need a separate metadata trail.
