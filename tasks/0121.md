# Task 0121: Era 1350 — Convergence-Driven Composite Health

## Status: COMPLETED | Priority: HIGH

## Context
Era 1340 produced `fleetConvergenceRate` — a Q16 metric of how
much of the network's known digest set this relay holds. The
metric was useful but isolated: nothing else in the stack
*reacted* to it. Era 1350 wires it into Era 1240's existing
composite health as a soft signal with bands and an alarm flag.

## Objective
1. Define a `ConvergenceHealthSignal` (score, band, alarm,
   intersection/network sizes) computed from local + network
   digest sets.
2. Provide `convergenceContribution(signal, weight)` returning
   an additive [-weight, +weight*0.1] term suitable for adding
   to a [0,1] composite.
3. Extend `RelayHealthInputs` and `CompositeOptions` minimally
   to fold the signal into existing composite calculations
   without breaking any prior caller.

## Acceptance Criteria

### 1. Signal Computation ✅
- [x] `computeConvergenceHealth(local_digests, network_digests, opts?)`
  returns `{rate_q16, score, band, alarm, intersection_size,
  network_size}`.
- [x] `rate_q16` matches Era 1340's `fleetConvergenceRate` exactly.
- [x] Empty network → score=1, band="converged", alarm=false.
- [x] Bands tunable: `converged_threshold`, `lagging_threshold`,
  `diverged_threshold`, `alarm_threshold`.

### 2. Contribution Math ✅
- [x] `convergenceContribution(signal, weight)`:
  - Reference point = `converged_threshold` (default 0.85).
  - Raw = `(score - reference) × weight`.
  - Capped at +weight*0.10 (small bonus only).
  - Floored at -weight (full downside).
  - Score exactly at `converged_threshold` → contribution ≈ 0.

### 3. Mesh Health Integration ✅

- [x] `CompositeOptions.weight_convergence` added with default 0.20.
- [x] `CompositeScore.contributions.convergence?: number` added
  (optional in output — omitted entirely when no signal provided).
- [x] `computeRelayHealth` folds the contribution into the raw
  composite when a signal is present.
- [x] `computeMeshHealth` averages convergence contributions only

## Design Notes
- **Why asymmetric contribution math?** Convergence is *expected*
  baseline behavior in a healthy mesh — getting a big bonus for
  doing the bare minimum would distort the composite. But falling
  behind is exceptional and warrants visible degradation. Capping
  the upside at 10% of the weight while allowing the full
  downside encodes this asymmetry.
- **Why optional `convergence` field in `contributions`?** Backward
  compat. Existing tests construct `CompositeScore` literals
  without the field; making it optional avoids cascading test
  updates. When the field is absent, downstream consumers
  (composite_monitor, HUDs) see no change.
- **Why aggregate convergence over only signal-providing relays?**
  In `computeMeshHealth`, summing across all relays and dividing by
  total count would dilute a small minority's lag signal. Dividing
  only by the count of contributors keeps the average representative
  of relays that actually reported.
- **Why a separate `convergence_health.ts` module instead of
  inlining into `mesh_health.ts`?** Era 1240's `mesh_health.ts`
  is already 230 lines covering four sub-signals; adding a fifth
  with its own bands, thresholds, and contribution math would push
  the file past the threshold where new contributors lose context.
  Keeping the signal definition in its own file with a clean public
  surface (compute / contribute / glyph) preserves locality.
