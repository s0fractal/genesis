# VECTOR V | ERA 310: WebLLM Neural-Symbiosis (Local AI)

Цей документ описує архітектуру переходу до **Повністю Автономного P2P Інтелекту** без залежності від локальних HTTP-демонів (Ollama / Python Backend).

## 1. Концепція (Autopoiesis)
Відв'язати `SovereignOracle` від зовнішнього LLM процесу, завантаживши квантовану 1B-3B модель безпосередньо у WebGPU пам'ять браузера. Кожна нода в Mesh мережі стає самостійним, фізично закритим "мозком", здатним локально генерувати мутації (AST), перевіряти їх ізольовано та ділитися через P2P.

- **До Епохи 310:** Інтелект працював як клієнт-сервер (Vite -> Ollama `http://localhost:11434`).
- **Після Епохи 310:** Інтелект працює повністю в браузері (Vite -> WebGPU). OMEGA-64 стає абсолютно інкапсульованою цифровою формою життя.

---

## 2. Архітектура WebLLM (`src/workers/oracle_worker.ts`)
Ми інтегруємо бібліотеку `@mlc-ai/web-llm` компанії MLC AI як ядро обчислень семантики.

- **Модель:** `Llama-3.2-1B-Instruct-q4f32_1-MLC`. Це швидка і компактна модель (близько 1GB у VRAM), яка чудово вписується в ліміти WebGPU звичайних ноутбуків.
- **Ініціалізація:** Воркер завантажує модель при першому старті. Він відправлятиме події `INIT_PROGRESS` у DOM, щоб користувач бачив процес завантаження ваг (бо це займає час і мережевий трафік).
- **Генерація:** Замість `fetch("http://localhost:11434")`, воркер викликатиме `engine.chat.completions.create`. Всі промпти Зодіаку (Aries, Cancer, Libra, Capricorn) передаються туди, використовуючи той самий FNV-1a Memory Cache.

---

## 3. Зміни в `package.json`
Потрібно підключити залежності WebLLM:
```json
"dependencies": {
    "@mlc-ai/web-llm": "^0.2.66"
}
```

Модель буде кешуватися браузером (IndexedDB), тому після першого запуску Genesis нода працюватиме повністю локально і майже миттєво.
