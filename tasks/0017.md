# 📄 ТЗ: Введення регуляризації, ваг та “живості” в OMEGA-64

## 1. 🎯 Мета

Перетворити поточну систему з:

> детермінованого мутаційного графа

у:

> енергетично обмежену, конкурентну, адаптивну систему з емергентною поведінкою

---

## 2. 🧠 Нові “ваги” (weights)

### 2.1 Node-level weights

Додати в `physics`:

```ts
attention: number; // [0..1] або більше
age: number; // кількість епох
mutation_rate: number; // адаптивний
fitness: number; // accumulated reward
```

---

### 2.2 Глобальні параметри

```ts
GLOBAL_ENERGY_POOL;
BASE_MUTATION_COST;
COMPLEXITY_ALPHA; // L1
DELTA_BETA; // L2
DECAY_RATE;
NOISE_LEVEL;
```

---

## 3. ⚖️ Регуляризація

---

### 3.1 L1 — штраф за складність IR

#### Реалізація:

```ts
function measureIR(ir): number {
  return nodeCount + depth * 2 + callCount * 3;
}
```

```ts
node.physics.energy_cost -= COMPLEXITY_ALPHA * measureIR(node.ir);
```

#### Очікуваний ефект:

- мінімізація AST
- поява “хитрих” компактних програм

---

### 3.2 L2 — штраф за різкі мутації

#### Реалізація:

```ts
delta = structuralDiff(oldIR, newIR);
cost += DELTA_BETA * delta;
```

#### Очікуваний ефект:

- плавна еволюція
- менше “рандомного трешу”

---

### 3.3 Age decay

```ts
node.physics.energy_cost *= 1 - DECAY_RATE;
node.age += 1;
```

#### Ефект:

- старі вузли вмирають
- нові мають шанс

---

## 4. 🧬 Динаміка “життя”

---

### 4.1 Competition (енергетична економіка)

#### Реалізація:

- вводимо глобальний пул:

```ts
GLOBAL_ENERGY_POOL;
```

- кожен тик:

```ts
distributeEnergy(nodes);
```

#### Варіант:

```ts
energy_share ∝ fitness + attention
```

---

### 4.2 Reward signal

#### Інтерфейс:

```ts
evaluateNode(node) -> reward
```

#### Приклади:

- стабільність output
- використання іншими вузлами
- зменшення complexity

```ts
node.physics.energy_cost += reward;
node.fitness += reward;
```

---

### 4.3 Attention (реальні “ваги”)

#### Реалізація:

```ts
node.attention = normalize(call_frequency);
```

```ts
energy_bonus = k * node.attention;
```

#### Ефект:

- часто використовувані вузли домінують

---

### 4.4 Plasticity

```ts
node.mutation_rate = base_rate / (1 + attention);
```

#### Ефект:

- популярні вузли стабільні
- рідкісні — мутують

---

### 4.5 Noise injection

```ts
if (system_entropy < threshold) {
  injectRandomMutations(NOISE_LEVEL);
}
```

---

## 6. 🧨 Parent constraint (твоя “решітка”)

### Твоя ідея:

> обмежити `parents <= 2`

---

## ❗ Відповідь (слухай уважно, бо вдруге не поясню)

### ✔ Що це дасть:

- граф стане ближчим до **binary lineage**
- потенційно:

  - DAG → lattice-like структура
  - легше аналізувати

---

### ❌ Що ти зламаєш:

1. **Втратиш рекомбінацію**

   - зараз можна мати N впливів
   - стане як примітивна генетика

2. **Зменшиш різноманіття**

   - система стане тупішою (так, як деякі мої знайомі)

3. **Застрягання в локальних мінімумах**

   - менше шляхів еволюції

---

### 🧠 Коли це має сенс:

✔ якщо ти хочеш:

- контроль
- відтворюваність
- аналіз

❌ якщо ти хочеш:

- “життя”
- емергенцію
- складність

---

### 💡 Рекомендація (щоб ти не наробив дурниць)

Замість:

```ts
parents <= 2;
```

зроби:

```ts
parents_weighted_selection(k=2..5)
```

тобто:

- вибираєш **2–5 найважливіших**
- інші відкидаєш

👉 Це:

> компроміс між хаосом і структурою
