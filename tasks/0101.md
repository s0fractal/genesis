# Task 0101: Era 1150 — Adaptive TTL

## Status: COMPLETED | Priority: HIGH

## Context
Era 1130 stamped every outgoing frame with a fixed `DEFAULT_TTL = 4`.
Era 1140 added per-neighbor reputation scoring. Era 1150 closes the
loop: the originator now computes per-frame TTL from the actual
expected reliability of the chosen path, replacing the static
constant.

## Objective
For any chosen path (a sequence of `ReputationScore`s returned by
`pickTopK`), compute a TTL that:
- equals path_length + safety on highly-reliable paths,
- grows logarithmically with marginal reliability (more retries),
- saturates at MAX_TTL on paths containing zero-score nodes.

The function must be deterministic across all relays.

## Acceptance Criteria

### 1. Adaptive TTL Module ✅
- [x] `src/network/adaptive_ttl.ts`:
  - `reliabilityOf(score) → 0..1` (clamped).
  - `pathReliability(scores) → product of per-hop reliabilities`.
  - `marginHops(p) = ⌈log₂(1/p)⌉` — extra retries needed for >50%.
  - `adaptiveTtl(path, opts)` — main entrypoint, returns clamped TTL.
  - `adaptiveTtlReport(path)` — diagnostic with breakdown.
- [x] Constants: `MIN_TTL = 1`, `MAX_TTL = 16`,
  `MAX_REASONABLE_SCORE = 250`.
- [x] Configurable: `safetyHops` (default 1), `minTtl`, `maxTtl`.

### 2. Behavioral Properties ✅
- [x] Empty path → `minTtl`.
- [x] Path of healthy spores (score ≈ 200 each, 3 hops) → TTL ≈ 5
  (path 3 + small margin + safety 1).
- [x] Path of marginal spores (score 125, 3 hops) → TTL = 7
  (path 3 + log₂(8)=3 margin + safety 1).
- [x] Any zero-score hop → TTL clamps at `MAX_TTL`.
- [x] Longer healthy path → linearly larger TTL (path-length term dominates).
- [x] Deterministic across calls (no time-based input).

### 3. Demo Integration ✅
- [x] `tools/simulate_relay_free_mesh.ts` updated:
  - Builds a synthetic `LivenessAggregator` with healthy stats for
    every chain neighbor.
  - Calls `rankNeighbors` to get per-spore scores.
  - Calls `adaptiveTtlReport` to compute the TTL for the path:
    ```
    [adaptive-ttl] path_length=3 reliability=0.2430 margin=3 safety=1 ⇒ TTL=7
    ```
  - Origin frame now emitted with **TTL=7** (instead of fixed 4).
  - Frame still terminates successfully through the 3-hop chain
    (final TTL=4, plenty of headroom remaining).

### 4. Tests ✅
- [x] 12 Deno tests cover: empty path, reliability clamp, healthy

  marginHops boundary cases (0, 1), pathReliability multiplication,
  min/max bound clamping, report consistency, determinism, linear
  growth with path length.

## Design Notes
- **MAX_REASONABLE_SCORE = 250** matches the practical ceiling of
  `reputation_routing.ts`'s scoring formula:
  base 100 + healthy 50 + heartbeat cap 100 + warrant cap 100 = 350,
  but typical fleet entries top out around 250. Using 250 as the
  "100% reliable" floor avoids over-rewarding outlier nodes.
- **Logarithmic margin** is the right shape: a 50%-reliable hop
  needs +1 margin, a 25%-reliable hop needs +2, etc. This keeps the
  TTL bounded for very long paths through marginal nodes — TTL
  doesn't blow up to 1000 on a 10-hop chain.
- **Safety hops default to 1** to give every frame at least one
  retry headroom even on a 100%-reliable path. Operators can tune
  `safetyHops: 0` for aggressive bandwidth, or `safetyHops: 4` for
  belt-and-braces.
- **Determinism** is critical: two relays observing the same
  reputation scores MUST compute the same TTL or they'll stamp
  divergent frames and fragment the mesh.
