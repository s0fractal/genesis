# Task 0155: Era 1690 — Translation Policy Corroboration Gate

## Status: COMPLETED | Priority: HIGH

## Context
Era 1680 could emit a warrant proposal from one local policy-drift
observation. That is useful for strict deployments, but planned schema
migrations can produce temporary single-observer disagreement. Operators
needed a configurable double/triple+ gate before warrant emission.

## Objective
1. Track policy-drift corroboration by independent witness id.
2. Use a timestamp-independent drift equivalence hash.
3. Expose lone/double/triple+/high confidence bands.
4. Add an optional gate to `TranslationPolicyInvestigationLoop`.
5. Preserve default single-observer behavior when no gate is configured.

## Acceptance Criteria

### 1. Equivalence Hash ✅
- [x] Drift equivalence excludes `observed_at_ms`.
- [x] Same peer/local-policy/peer-policy mismatch converges across

- [x] Different peer or policy hashes produce different records.

### 2. Corroboration Tracker ✅

### 3. Loop Gate ✅
- [x] Optional gate accepts `tracker`, `witness_id`, and

- [x] Below-band drift blocks proposal emission and increments

- [x] Pre-corroborated external witness + local witness emits when the

- [x] No gate preserves Era 1680 single-observer emission.

### 4. Telemetry ✅

### 5. Tests ✅
- [x] Corroboration tracker test suite passes.
- [x] Policy investigation loop test suite passes with and without gate.

## Design Notes
- **Why ignore timestamp in the corroboration hash?** Independent relays
  will observe the same policy mismatch at different times. Corroboration
  should bind to the semantic mismatch, not the local wall-clock.
- **Why keep default mode as single-observer?** Some deployments want
  immediate strict policy enforcement. Era 1690 adds an operator gate
  without changing default behavior.
- **Why not auto-sync witness records yet?** This era defines the local
  evidence model. Wire exchange is a separate boundary and becomes the
  next era.
