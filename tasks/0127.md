# Task 0127: Era 1410 — SporeFrame Wire-Format for Event Sync

## Status: COMPLETED | Priority: HIGH

## Context
Era 1390 defined a pure event-delta protocol; Era 1400 ported the
sink to Rust. Era 1410 ships the delta over the wire using the
same 32-byte SporeFrame format Era 1320 already uses for archive
syncs. A spore can now exchange event-log convergence packets
with a JS relay over UART/SPI/BLE, no other transport needed.

## Objective
1. Reserve `FRAME_TYPE_EVENT_HASH_LIST = 9` and
   `FRAME_TYPE_EVENT_DELTA_CHUNK = 10` in BOTH Rust and JS frame
   registries.
2. JS chunker/reassembler for `EventDelta` envelopes mirroring
   Era 1320's `archive_sync_wire.ts` semantics.
3. Compact kind-tag encoding so 4-byte kinds round-trip through a
   u32 payload slot.
4. Locked Rust test pinning the entire frame-type registry as a
   single fact.

## Design Notes
- **Why pack kind into a single u32?** Bare-metal nodes don't
  allocate, and a 4-byte slot is a single `payload_b` field in
  the existing 32-byte frame. Truncating to 4 ASCII chars
  matches the spore's `MAX_KIND_LEN = 16` cap structurally
  (kinds shorter than 4 chars still pack cleanly with null
  padding) while keeping the wire layout aligned to the
  existing slot grid.
- **Why reuse Era 1320's envelope structure verbatim?** Two
  benefits. First, code review surface: a reader who knows Era
  1320 immediately understands Era 1410 — header at seq=0,
  records at seq=1..N, envelope_hash in `tick`. Second, future
  generic chunker (if a third such store appears) becomes
  natural: identical structure invites factoring.
- **Why pin the *entire* frame-type registry in one Rust test
  instead of per-type tests?** A single test failing on any
  registry change is more obvious to a reader scanning CI than
  ten near-identical tests. Cross-substrate registry drift is
  a single fact: "JS and Rust agree on frame-type IDs", and
  the test should reflect that fact.
- **Why does the wire form set `sequence = 0` and
  `prev_chain_hash = 0` on imported entries?** Era 1390's
  `applyEventDelta` re-runs `sink.append` locally, which assigns
  fresh sequence numbers and chain hashes. Imported entries are
  not expected to carry source-side chain links — only the
  cross-Era content address (`event_hash`) is preserved. Setting
  these fields to zero in the reassembled struct is informational
  only.

## Next Era Trigger
**Era 1420: Spore-Initiated Event Broadcast.** The Cortex-M4F
spore can hold an event log (Era 1400) and decode chunked deltas
(Era 1410), but it can't yet ORIGINATE an `EventHashList`
broadcast or relay another peer's `EventDeltaChunk` traffic —
both still require the JS side to drive. Era 1420 will add the
firmware-side helpers: `build_event_hash_list_frame`,
`build_event_delta_chunk_frame`, plus a small forwarding
state-machine that routes incoming chunks toward configured
upstream relays. Once landed, a spore is a first-class
convergence participant, not just a passive sink-holder.
