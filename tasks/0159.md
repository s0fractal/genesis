# Task 0159: Era 1730 — Translation Policy Peer Directory Integration

## Status

✅ COMPLETED

## Context

Era 1720 introduced deterministic outbound broadcast scheduling for local
translation-policy claims, but its known-peer table still had to be
populated manually. WebRTC already owns connection lifecycle, while the
scheduler should remain transport-agnostic.

## Implementation

- Added `src/network/translation_policy_peer_directory.ts`.
- Introduced `TRANSLATION_POLICY_PEER_DIRECTORY_SCHEMA = "OMEGA-1730/v1"`.
- Added `deriveTranslationPolicyPeerId(...)`:
  - numeric ids are normalized as `u32`;
  - string ids are deterministically FNV-1a hashed.
- Added `TranslationPolicyPeerDirectoryAdapter`:
  - listens to configurable join/leave/activity events;
  - adds peers on joins;
  - removes peers on leaves;
  - adds/refreshes peers on translation-policy claim/corroboration
    activity;
  - exposes lifecycle, malformed, add/remove, and activity telemetry;
  - uses the same `EventSource` contract as other lifecycle bridges.
- Added passive `meshPeerJoined` / `meshPeerLeft` `CustomEvent`s in
  `src/network/webrtc_v2.ts` when DataChannels open/close.

## Tests

- `tests/translation_policy_peer_directory_test.ts`
