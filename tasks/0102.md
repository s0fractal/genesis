# Task 0102: Era 1160 — Path Selection by Reputation × TTL Budget

## Status: COMPLETED | Priority: HIGH

## Context
Era 1140 ranked individual neighbors. Era 1150 turned per-frame TTL
into a function of path reliability. Era 1160 closes the loop: when
the originator can route through several different paths, pick the
one with the best (reliability / TTL) tradeoff. A 2-hop healthy path
that arrives in 5 hops total of TTL beats a 5-hop marginal path that
needs 12 — even if both end up with similar end-to-end reliability —
because the shorter path costs less mesh radio time.

## Objective
Provide `rankPaths` and `pickBestPath` API that takes multiple
`PathCandidate` objects and returns them ordered by an efficiency
score that combines reliability with TTL budget cost.

## Acceptance Criteria

### 1. Path Selection Module ✅
- [x] `src/network/path_selection.ts`:
  - `PathCandidate { label, hops: ReputationScore[] }`.
  - `PathRanking { label, hops, reliability, ttl, efficiency, eligible }`.
  - `rankPath(candidate) → PathRanking` — single-path scoring.
  - `rankPaths(candidates) → PathRanking[]` — sorted descending.
  - `pickBestPath(candidates) → PathRanking | null` — top eligible
    or null if all are forked.
  - `evaluatePath(hops, label?) → PathRanking` — convenience wrapper.

### 2. Efficiency Formula ✅
```
efficiency = (reliability × 1000) / ttl
```
- Higher efficiency ranks first.
- Forked candidates → `efficiency = 0, eligible = false` and rank
  AFTER all eligible candidates regardless of math.
- Tie-break: shorter path → lexicographic label asc (deterministic).

### 3. CLI Demo ✅
- [x] `tools/spore_relay.ts --paths` synthesizes 3 candidate paths

- [x] Demonstrates that fork-tainted path is correctly excluded

### 4. Tests ✅

  mutation of input, edge case for empty hops list.

## Design Notes
- **Why (reliability × 1000) / ttl?** This biases toward paths with
  fewer total radio transmissions. A 2-hop path with TTL=4 means at
  most 8 over-the-air emissions; a 5-hop path with TTL=12 means up
  to 60. Even if both deliver, the latter is 7.5× more expensive.
- **Why include ineligible paths in `rankPaths` output?** Operators
  want to SEE why a path was excluded (the `eligible: false` flag
  surfaces drift in the HUD even if it can't be used).
- **EFFICIENCY_SCALE = 1000** keeps the numbers human-readable in
  the typical range (~10..400) without needing floating-point
  precision games.
- **Determinism contract**: same candidates → same ranking order
  on every relay. Stable tie-break by `label` ascii guarantees this.
