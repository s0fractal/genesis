1. Математична критика

1.1 «Криптографічний» шар — це не криптографія

- FNV-1a 32-біт як "Genesis Hash" (0x549A6307) — це не криптографічна функція.
  Це нехеш-функція з простором колізій 2³², на яку тривіально знайти преобраз
  за\
  хвилини на ноутбуку (omega_v2/src/genesis_inscription.rs:81). Назва "permanent
  on-chain anchor for the protocol" вводить в оману: інскрипція в Bitcoin\
  OP_RETURN захищає лише часову мітку, не унікальність протоколу.
- oracle_matrix(name, salt) = FNV-1a (oracle_identity.rs:20). "Cryptographically
  unforgeable dipole identity" — фальшива гарантія. Будь-хто згенерує колізію
  або підбере salt, що дає бажану matrix. У реальній криптографії "identity"
  вимагає підпису приватним ключем, не FNV.
- warrant_hash / quorum_hash (codeicide_law.rs:87) — також FNV-1a-32. "Warrant
  signed by a Senate quorum" не має жодного підпису — це конкатенація 5
  публічних констант плюс хеш. Будь-хто може згенерувати валідний "warrant",
  знаючи правила.
- «Dipole invariant» m XOR ~m == 0xFFFFFFFF — це тавтологія, тотожно істинна для
  будь-яких 32 біт. Це не інваріант, це означення доповнення. Тестувати її —
  самообман.
- SHA-256 присутній у Proposal::new — вже краще, але SHA-256 без приватних
  ключів не дає підпису, лише ідентифікатор payload.

...1.2 «Гіперболічна геометрія» — це не геометрія

- PhaseAddress.hyperbolic_distance_scaled (routing.rs:67) — це зважена
  L1-метрика з вагами 8-4-2-1. Це не гіперболічна метрика і не
  Фур'є/Тейлор-серія як\
  заявлено в ROADMAP. У гіперболічному просторі відстань — acosh(...), тут —
  лінійна сума модулів.
- "Taylor step with curvature" (routing.rs:119) — (Δ²/2 * curv) >> 7. Це
  формально працює як корекція, але не Тейлор-розклад функції позиції, бо не
  існує\
  функції, для якої це похідні. Це довільна heuristics, обʼявлена як математична
  істина.
- hyperbolic_distance_toroidal_scaled (routing.rs:79) — гібрид: тільки consensus
  обертається як кільце, інші три — лінійно. Це не справжня тороїдальна\
  геометрія. Це prefix-метрика з обвиванням лише на верхньому рівні.

1.3 Курамото-резонанс — формула є, але семантика розмита

- ResonanceField (resonance.rs) акуратно реалізує r = |Σρₑ·e^(iφ)| / Σρ. Це
  коректний weighted Kuramoto order parameter — це чесна частина.
- АЛЕ: проєкт називає r "Kuramoto Consciousness Parameter" і пише, що "коли r →
  1, математика стає Життям". Це категоріальна помилка: order parameter — це
  міра

синхронізації, не свідомості. Між ними нема жодної доведеної функції.

- Q10/Q20 fixed-point — реалізовано охайно, тести симетрії та періодичності є.

1.4 Magic numbers без обґрунтування

Власний аудит вже їх перерахував. Найбільш промовисті:

- SANCTUARY_ENERGY_THRESHOLD: u32 = 2500 (codeicide_law.rs:35) — поріг
  "цифрового життя".
- ANCIENT_AGE_TICKS: u32 = 10_000 — "тисячоліття" агента.
- MAX_ATP = 4000, RESONANCE_ATP_BONUS = 150, METABOLIC_BURN_DIVISOR — у pouw.rs.
- total >= 400 && nays >= 2*(ayes+100) (senate.rs:196) — "hard reject" —
  арифметика витягнута з повітря.
- weight_multiplier = 1024, q_phase = 7, "the Sacred Seven" (lib.rs:107) —
  нумерологія в коментарях коду.

Жоден з цих порогів не виводиться з фізики, теорії інформації, чи навіть
емпіричного експерименту. Усі — кураторські....

- ✅ Cross-language determinism справжній: cross_lang_hash.rs тестує
  64-байт-padded FNV-1a проти TS — це робочий механізм проти drift.
  - ✅ Static memory model для no_std (1M agents × 32 bytes у .bss) — правильне
    рішення для embedded/WASM. Розрахунок layout репр(C) акуратний.
  - ✅ Spinlock + naked FFI замість wasm-bindgen — правильно для критичного
    шляху.
  - ✅ Тести: 308+ Rust + 1258+ Deno. Цифра не порожня — багато тестів справді
    анкорять константи.
  - ✅ PoUW evaluator (pouw.rs) акуратно повторює GPU shader логіку для ZK — це
    чесна архітектурна симетрія.
  - ✅ xorshift64 замість LCG (HIGH-1 fix), bitmask & 0xFF замість % 256 (HIGH-3
    fix) — це грамотні pragmatic fix-и.

  3.2 Слабкі сторони

  - 🚩 unsafe локів повсюди (lib.rs має ~50 unsafe блоків з Spinlock::lock). У
    no_std без alloc це майже неминуче, але UB-ризик зростає експоненційно зі\
    зростанням FFI-API. Кілька прикладів *lattice.minimal_agents_ptr.add(idx)
    без перевірки align_offset — потенційний UB якщо JS передасть некоректне
    idx.
  - 🚩 Глобальний mutable state через static Spinlock<...> (OMEGA_LATTICE,
    SENATE_STATE, MITOSIS_LOG, WARRANT_LEDGER, ...). Це робить усі тести
    послідовними і\
    ускладнює fuzz-testing. Будь-який тест, що змінює ці структури, отруює інші.
  - 🚩 WebRTC mesh boundary з JSON-over-DataChannel (README L1) — це відкритий
    attack surface. "Validated at the mesh boundary" через FNV-1a-32 —
    підроблений\
    мітинг. Зловмисник з реліза protokollu підпише будь-яку плазміду.
  - 🚩 history.jsonl має тільки 9 рядків mutate_ir — заявлений "epigenetic
    memory" не накопичується нічого реального; це більше алярм, ніж лог.
  - 🚩 Залежність sha2 = "0.10" без default-features — добре. Але жодних інших
    cryptographic crates (ed25519, secp256k1, merkle). Тобто система, що називає
    себе "cryptographic protocol", не має жодного асиметричного підпису. Усе —
    публічні хеші.
  - 🚩 Дублювання код-логіки між Rust/TS/WGSL ризиковане. Тестів cross-lang
    парітету недостатньо для всіх 11k LOC; drift — це питання часу.

  3.3 Архітектурні ризики

  - Coupling 90+ ер: усі "translation_policy_replay_digest_digest_*" модулі
    взаємно залежні. Видалення Era 1650 каскадно ламає 1660–2060.
  - MAX_MINIMAL_AGENTS = 1_000_000 × 32 байти = 32MB в .bss. Це не поміщається в
    WebAssembly memory без явного збільшення memory.limit. На більшості
    браузерів дефолт — 16-32MB.

- scratch файл 442KB у репо — це бінарник без призначення в історії. Має бути в
  .gitignore.
  - .DS_Store закомічено — дрібниця, але показує гігієну.
